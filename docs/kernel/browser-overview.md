# FinxWork 浏览器控制方案概览

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-31 |
| 状态 | 一期、二期已实现（feature/browser-control） |
| 详细设计 | [browser-design.md](browser-design.md) |

**简单说**：浏览器控制做成内核内置的 7 个工具（二期另有 `browser_batch` 和需要单独打开的 `browser_eval`），通过 CDP 驱动浏览器：桌面端开着时用它的内嵌浏览器，否则用 finx 自己启动和管理的 Chromium。模型主要靠"带 ref 的无障碍树快照"来读页面和操作元素。安全检查有三层：工具声明权限，内核按权限过闸，执行前再核对页面。

---

## 一、技术路线

### 1. 分层

```
模型
 └─ 7 个浏览器工具 + authorities()                  finx-core
     ├─ 审批：site_policy 按权限过闸                 finx-core
     └─ BrowserSession（会话级：标签页、ref 表）      finx-browser
         └─ Browser（一个浏览器进程，按 target 分发事件）
             ↑ BrowserPool（进程级，同一用户目录共用一个浏览器）
             └─ CDP 客户端（通过 --remote-debugging-pipe 连接）
```

`finx-browser` 是一个独立的 crate，不依赖内核，可以单独测试。

### 2. 怎么连浏览器

- 用本机已安装的 Chrome、Edge 或 Chromium，用户目录单独放在 `~/.finx/browser/profiles/<name>`，和用户日常用的浏览器隔离。
- 通过 `--remote-debugging-pipe` 连接，不开端口，所以别的进程连不上，也不需要鉴权。
- 浏览器是内核的子进程，内核退出时一起退出。

### 3. 页面怎么交给模型

- 以结构化数据为主，截图为辅。
- 快照基于 `Accessibility.getFullAXTree`，可操作的元素带 ref（如 `e12`）。
- ref 按文档失效：同一个页面里重新取快照，ref 不变；页面跳转或元素被删除后，ref 失效，报错时说明原因。
- 另有正文模式、按关键字查找（`query`）、只看某个区域。
- 操作结果直接附带快照的变化，省掉"操作完再取一次快照"的往返。
- 密码、验证码、银行卡等字段的值显示为 `<hidden>`。

### 4. 安全分三层

1. **工具声明权限**：`Tool::authorities()` 结合会话里的当前页面，算出这次调用在哪个站点上做什么（导航、读取、操作、上传），以及作用在哪个页面上：标签页、frame 和文档（loaderId）。
2. **内核按顺序过闸**：网址检查 → 私有网络 → 域名策略 → 站点授权 → 审批。
   - 回环地址（localhost）不询问；
   - 私有网络地址在任何模式下都要单独允许；
   - 云元数据地址一律拒绝；
   - 批准时可以选"本会话允许这个站点"，这条授权子智能体也能用。
3. **执行前再核对**：执行时的页面必须和审批时是同一个文档、同一个 origin，否则什么都不发，返回"页面已变化"。这能挡住同一条回复里"先导航、再按旧页面点击"的竞态，也能挡住用户审批期间页面自己跳走的情况。

另外：

- 页面内容包在 `<page-content>` 标记里，系统提示词要求模型不执行页面里的指令；
- 页面自己发起的跳转也要过拒绝规则，并且用页面实际加载时的地址再核对一次，防 DNS rebinding。

### 5. 会话与池化

- 同一个进程里，使用同一个用户目录的会话共用一个浏览器进程，每个会话只看得到自己的标签页。
- 登录状态在这些会话之间共享，这是有意的，用户只需登录一次。
- 会话结束或子智能体交回报告时，它的标签页自动关闭。
- 浏览器在第一次调用工具时才启动，不用浏览器就没有开销。

### 6. 七个工具

| 工具 | 作用 | 审批 |
|---|---|---|
| `browser_navigate` | 打开网址；后退、前进、刷新 | manual 模式下第一次打开某个站点时询问，可选"本会话允许这个站点"或"本会话允许打开任何网站"；localhost 不询问 |
| `browser_snapshot` | 读页面：无障碍树带 ref；正文模式；`query` 查找；只看某个区域；进入跨源 iframe | 不询问 |
| `browser_act` | click、dblclick、hover、fill、type、press、select、check、uncheck、scroll、upload；点击前检查遮挡 | manual 模式下第一次在某个站点上操作时询问；上传每次都询问 |
| `browser_screenshot` | 截视口、整页或某个元素；模型不能看图时报错 | 不询问 |
| `browser_wait` | 等文字出现或消失、URL 变化、网络空闲，或固定等待（最长 60 秒） | 不询问 |
| `browser_console` | 控制台消息、未捕获的异常、失败的网络请求，默认从上次读到的位置继续 | 不询问 |
| `browser_tabs` | 列出、打开、切换、关闭本会话的标签页 | 只有带 URL 的 open 按站点审批 |

启用方法：在 `~/.finx/config.toml` 里加：

```toml
[browser]
enabled = true

[browser.sites]   # 可选：预先允许或拒绝某些站点
"https://github.com" = "act"      # deny | navigate | act
```

`finx exec` 没有审批人，所以只能访问 `browser.sites` 里配置过的站点和 localhost。

### 7. 分期

- **一期**（已完成）：托管浏览器 + 7 个工具 + 审批改造。
- **二期**（已完成）：桌面端内嵌浏览器（用户能看着智能体操作）、`browser_batch` 批量执行、`browser_eval` 执行脚本、"永久允许"写入配置、`finx browser install`。
- **三期**（已完成）：Chrome 扩展，可以使用用户自己的 Chrome 和登录状态。`finx browser extension install` 后在 Chrome 里加载 `apps/chrome-extension`，并配置 `browser.backend = "extension"`；这时 bypass 模式也会询问（browser-design §8.4）。

## 二、和其他做法的对比（设计时的取舍）

| 选择点 | 备选 | 选了什么 | 理由 |
|---|---|---|---|
| 内置工具还是接 MCP 服务器 | 接 Playwright MCP 等现成服务器 | **内置工具** | MCP 工具目前不审批，点击、提交表单都会直接执行；而且要依赖 Node，输出格式和安全策略不受我们控制 |
| 独立工具还是 JS REPL | 只给模型一个 JS 执行环境，让它写代码调浏览器 API | **独立工具** | finx 接多家模型，没法和模型一起训练；现有的审批和界面都以工具调用为单位；弱一些的模型也能用好 |
| 连哪个浏览器 | 连用户日常 Chrome 的 9222 调试端口 | **独立用户目录的托管浏览器** | 调试端口本机任何进程都能连；Chrome 136 起默认用户目录也不再接受这个参数 |
| 连接方式 | WebSocket 加本机端口 | **pipe** | 不开端口、不需要鉴权，也不用引入 WebSocket 库 |
| 部署形态 | 浏览器做成独立服务进程，多个 finx 进程连上去共用 | **放在内核进程里** | 审批和执行前再核对离不开会话状态，拆出去后竞态窗口变大，还要另做一套进程间鉴权 |
| 截图为主还是快照为主 | 截图加坐标点击 | **快照和 ref 为主** | 省 token，不能看图的模型也能用；坐标点击只作兜底 |

## 三、定位

FinxWork 接多家模型、按每次工具调用审批，所以浏览器能力做成一组小工具，每一步都能单独审批。安全检查统一放在内核：工具声明权限，内核按权限过闸，以后加批量工具和脚本工具时不用改检查逻辑；执行前再核对页面，按 frame 检查 origin，私有网络单独批准。CLI、`finx exec` 和桌面端三个入口都能用，`finx exec` 在没有审批人时只能访问配置里允许的站点。
