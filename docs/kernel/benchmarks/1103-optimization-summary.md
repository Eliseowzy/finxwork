# 1103 交接之后的优化总结

日期：2026-11-03

范围：接手 1103 批次（PR #5）之后同一天的全部性能工作，包括并发负载、启动、长任务和单次任务内存。测量陷阱、走不通的路和定位方法见 [性能工作手册](performance-playbook.md)，逐项的数据与损益分析见 [第二轮报告](1103-round2-performance-report.md)，设计层面的记录见技术方案 v1.35 的 §1.4、D-96、D-97、D-91 和 Q-20。

基线：`692cb94`（1103 批次合入后的主干）。

## 1. 结论

| 200 个会话满载（macOS）：任务 p95 | 541 ms | 286 ms | **−47%** |
| 同上：每秒完成的任务 | 354 | 669 | **+89%** |
| 首包 100 ms 的 200 个会话：任务 p95 / 吞吐 | 1885 ms / 102 | 1501 ms / 129 | −20% / +26% |

## 3. 方法

- **棘轮规则**：任何改动都不许让任何指标出现可复现的退化，也不能影响用户体验和功能。
- **对照方式**：同一台机器、同一个驱动，基线与候选交替运行，取中位数并做 Mann-Whitney 检验。启动类指标在两次重编之间会漂移约 ±2%，必须复现才算数。
- **macOS**：Apple M2 Max 12 核。**Linux**：1 vCPU 的 AMD EPYC-Milan，静态 musl 构建，fork 之前取时。
- **负载**：`finx-sim` 原生协议、宏观研究场景、200 个会话。分两种：
  - 真实延迟：首包 100 ms、工具 10 ms、共用一条连接；
  - 满载：不等待、每个会话一条连接。
- **单次任务内存**：连真实 DeepSeek 服务跑一次任务，与一个同类原生 CLI 的正式版用同一模型、同一提示交替运行。
  - macOS 取峰值物理占用（`/usr/bin/time -l`）；
  - Linux 取峰值 RSS，并读 ACP 任务后的匿名内存。

## 4. 主要发现

- **满载瓶颈是 F_FULLFSYNC**：采样显示服务进程 63% 的非空闲线程时间耗在会话日志的 write 和 F_FULLFSYNC 上；macOS 的硬盘一次只做一个冲刷，200 个任务同时结束就排成长队。
- **冷启动瓶颈是首次执行冷代码，而不是计算**：clap 第一次解析要 557 µs，之后每次 34 µs；一次 `finx exec` 有 389 次缺页，空进程只有 56 次。mimalloc 反而让 Linux 启动慢了 21% ～ 28%。
- **长任务每轮的开销**：33% 是写文件工具的写屏障（保护用户文件，不动），18% 是每轮重新序列化整段历史（Q-96）。
- **单次任务内存的构成**：
  - 跑任务本身，finx 比对照程序涨得少；差距在启动时的固定开销和建会话。
  - 任务后真正活着的堆约 650 KiB，malloc 的脏页约 2.2 MiB：多出来的是用完被释放、分配器留着的临时分配；macOS 的分配器不响应 `malloc_zone_pressure_relief`。
  - 链接 CoreFoundation/Security 会连带装载约 700 个系统镜像，内存约 1.2 MiB（ObjC 初始化的堆约 490 KiB，加上数据段脏页），另加启动约 1 ms。对照程序只链接 libSystem。
  - Linux 上 RSS 多出的是二进制代码页，同一个二进制的多个进程共用一份，不处理。

## 5. 未完成与待决策

| 事项 | 状态 |
|---|---|
| macOS 不默认链接系统框架（TLS 先用内置根证书，必要时再加载 Security） | 约 −1.2 MiB、−1 ms；涉及安全敏感代码，待决策（Q-20） |
| stdio 传输不限制单行长度 | 连续发送不含换行的数据时内存会无限增长（实测 2.1 GB），待修 |
| CI 的本地命令 2 ms 门槛 | 已查明并改掉：门槛频繁变红主要是 runner 波动，同时有一次真实变慢。门槛改为缺页预算，见 [1105 报告](1105-local-command-gate-report.md) |
| 冷启动减半 | 需要 PGO、快速参数解析等，代价与预估见第二轮报告 §4.1 |
| 长任务每轮开销 | 缓存历史的序列化结果可降 15% ～ 20%，代价是内存（Q-96） |
| 每次请求深拷贝工具定义与系统提示词 | 每次请求约 30 KiB 和相应的 CPU，留到 CPU 那一轮 |
