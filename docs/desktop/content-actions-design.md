## 方案摘要

- **要做的事**：会话内容区里的文件路径、网页链接、代码块从"只能看"变成"能操作"。工具步骤行和选中的文字也有右键菜单。
- **文件路径变成文件标签**：
  - 样子：图标、名字、灰色的行号；
  - 左键：用"默认打开方式"打开；
  - 右键：打开 / 打开方式 › / 在访达中显示 / 拷贝路径 / 拷贝相对路径。
- **网页链接**：
  - 样子：前面加小图标，太长的网址中间省略；
  - 左键：在当前会话的内置浏览器打开；⌘ + 左键：在默认浏览器打开；
  - 右键：在内置浏览器中打开 / 在 X 中打开 / 拷贝链接。
- **代码块**：
  - 顶部加标题栏，左边是语言名，右边是"拷贝"按钮；
  - 命令块（bash 等）多一个"在终端中打开"：打开系统终端，同时拷贝好命令。
- **识别在页面里做**：以 Markdown 的语法树为准。文件只认两种写法（文件链接、行内代码），行内代码里的路径还要本机确实存在。
- **动作在主进程做**：动手前再查一次目标；一打开就会运行的文件，点击只在访达中显示。
- **渲染只是展示**：显示消息、加载历史、流式生成都不联网，不读文件内容，不执行任何东西。
- **内核**：
  - 桌面会话的系统提示词多一段两行的格式约定；
  - `browser/site_icon` 加只读缓存的参数。
- **不在这一期**：运行按钮、应用内文件预览、模型主动打开面板、普通文字里的路径。
- **工作量**：约 4 天（§12）。

## 1. 现状

会话正文用 react-markdown 加 remark-gfm 渲染（`session/Markdown.tsx`），问题有五个：

- **http 链接点了没反应**：主窗口打开新窗口的处理只放行 https（`main/windows.ts`）。`http://localhost:5173` 这类本机开发服务的地址，点了什么也不发生。
- **文件链接成了纯文字**：链接目标不是 http、https 时，渲染成一个 `<span>`。模型写的 `[配置文件](src/config.ts:42)` 只显示"配置文件"四个字，路径看不到，也点不了。
- **代码块只有着色**：没有语言名，也没有拷贝按钮，要拷贝只能手动选中。
- **内容区没有右键菜单**：选中文字后右键什么都没有，只能用 ⌘C。
- **提示词里只有一句** "Refer to code as path:line"，没有链接和命令块的写法约定。

能用的底层已经有了：
- 原生右键菜单（`popupMenu`，会话列表在用）；
- 在访达中显示、在终端中打开文件夹、用默认浏览器打开链接；
- 每个会话自己的内置浏览器面板；
- 站点图标的缓存（browser-design §10.2）。

缺的是内容区自己的识别和入口。

## 2. 目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 看得出、点得开 | 回复里提到的文件和网页，一眼看得出是什么，一下就能打开 |
| G2 | 就地操作 | 拷贝、定位、打开都在原地完成，不用先选中文字 |
| G3 | 渲染只是展示 | 显示消息、加载历史、流式生成都不联网，不读文件内容（只查存不存在），不执行任何东西；所有动作都要人来点 |
| G4 | 所见即所得 | 拷贝的、打开的，就是显示的那一个。名字可以和目标不同，悬停时能看到真实目标 |
| G5 | 与现有界面一致 | 令牌、圆角、菜单、文案都沿用现有的（desktop-design §5） |

两条原则：
- **宁可漏认，不要错认**：认错一个，比少认一个更糟。版本号、分支名、包名、命令不能变成文件。
- **界面只是指路，主进程才是把关的人**：页面上的识别结果只是提示，主进程动手前自己再查一次。

## 3. 识别

### 3.1 认什么

| 写法 | 认成 | 条件 |
|---|---|---|
| `[名字](路径)`：链接目标不是网址 | 文件标签 | 不管文件存不存在都显示成标签，不存在时置灰 |
| `[名字](http://…)`、`[名字](https://…)`、正文里的裸网址 | 网页链接 | 只认 http、https |
| `` `路径` ``：行内代码 | 文件标签 | 长得像路径（§3.3），而且本机确实存在 |
| `` `https://…` ``：整段行内代码就是一个网址 | 网页链接 | 网址里没有 `{}`、`<>` 这类占位符；仍是等宽字体 |
| 带围栏的代码块 | 代码块 | 都加标题栏；bash 等算命令块（§6.2） |
| 普通文字里的路径、代码块里的路径、`mailto:` 等其他链接 | 不变 | 和现在一样 |

识别在 Markdown 的语法树上做（react-markdown 的组件覆盖），不在渲染出来的 HTML 上替换字符串。这样代码块里的示例路径不会被误认，转义和嵌套结构也不会被破坏。

react-markdown 默认会清掉它认为不安全的链接目标：`README.md:12` 被当成协议名是 `README.md` 的网址，`file:///…` 的协议不在白名单里。所以要自己处理链接目标：
- 链接目标原样交给识别；
- 只有 http、https 的网址才会成为页面上真正的 `<a href>`；
- 其余的要么成为文件标签（一个按钮，点击由程序处理），要么成为纯文字。

### 3.2 文件链接的目标

- **路径**：
  - 相对路径，相对会话的项目目录（§3.4）；
  - 绝对路径；
  - `~/` 开头的路径；
  - `file://` 网址；
  - Windows 上还有盘符路径。
- **行号**，写在末尾，从 1 开始：
  - `:42`、`:42:7`（列号不用）；
  - `#L42`、`#L42-L60`；
  - `:42-60`。
- **编码**：路径按网址编码解开（`%20` 是空格）。解码失败就用原文。
- **不是文件的**：
  - 带其他协议的目标（`mailto:`、`tel:`、`javascript:`、`data:` 等）仍是纯文字；
  - `#` 开头的锚点也是纯文字（这一期没有应用内的资源）。

### 3.3 行内代码里的路径

只认长得明确像路径的：

- 只有一行，不超过 300 个字符；
- 不含 `*`、`?`、`<`、`>`、`|`、`"`（通配符和 shell 符号），不含 `://`，不以 `-`、`$`、`@` 开头；
- 有空格时，必须以 `/`、`~/`、`./`、`../` 开头；
- 路径部分满足下面一条：
  - 含 `/`（Windows 上也可以是 `\`）；
  - 以扩展名结尾（`.` 加 1 到 8 位字母或数字）；
  - 是常见的无扩展名文件：`Makefile`、`Dockerfile`、`LICENSE`、`Gemfile`、`Procfile`、`Justfile` 等；
- 末尾可以带行号，写法同 §3.2。

满足这些只是候选。主进程查过本机存在，才显示成文件标签；不存在就保持行内代码。

所以：
- `feat/x`、`origin/main`、`v1.2/3`、`cargo test`、`@finx/client`、`src/**/*.ts` 都不会变成文件；
- 一个单词 `src` 不是候选；`src/`、`apps/desktop` 是候选，存在时显示成文件夹。

### 3.4 相对路径的基准

- 相对路径按**消息所属会话**的项目目录解析（`SessionInfo.cwd`），不是应用的启动目录，也不是当前选中的另一个会话。
- 子智能体的汇报卡片、后台任务卡片里的执行过程，都按同一个会话的目录解析。
- 不在会话里的地方（自定义页的技能详情）：文件不识别，和现在一样；代码块的标题栏照样有，网页链接用默认浏览器打开。

### 3.5 生成中的内容

正在生成的回复由同一个 `Markdown` 组件处理。按语法树分块并保留尾部回看，完成块缓存，最后一块仍在变化；引用式链接、脚注需要整篇解析时，保守地把整篇作为草稿：

- 写完的块照常识别；
- 最后一块：
  - 链接和路径显示成纯文字和行内代码，不查存在性；
  - 代码块有标题栏和语言名，但没有按钮；
- 整条回复写完，只更新草稿状态再识别，不卸载已有代码块、表格或折叠内容；
- 文档引用和本机图片也遵守草稿状态，避免半截引用触发定位或读取。

这样半截的链接不会被点开，没写完的命令也拷贝不了。

### 3.6 存在性检查

- **怎么查**：页面把候选路径攒成一批（一帧一次），交给主进程的 `pathInfo(base, paths)`。
- **主进程做什么**：
  - 解析成绝对路径，用 `stat` 查是文件、文件夹，还是不存在；
  - 能算出相对路径的（在项目目录里），一并给出；
  - 不读文件内容。
- **缓存与重查**：
  - 页面按"项目目录 + 写法"缓存结果；
  - 会话的任务结束时、窗口回到前台时，正在显示的路径重查一遍，因为智能体可能刚建了或删了文件；
  - 结果变了的标签跟着更新。

## 4. 文件标签

### 4.1 样子

- 行内的小标签，结构是：图标（文件或文件夹）、名字、灰色的行号（`:42`）。
- 颜色和字体：
  - 底色 `--fill`，0.5 像素描边，圆角 `--r-xs`，名字用链接色 `--accent-t`；
  - 来自行内代码的用等宽字体，来自链接的用正文字体。
- **名字**：
  - 链接：链接文字；
  - 行内代码：代码原文，行号部分拆出来显示成灰色。
- **悬停**：
  - 底色加深；
  - 提示真实目标：项目里的显示相对路径，项目外的显示完整路径，有行号时加上"第 42 行"。
- **不存在**（只有链接会出现）：名字置灰，提示"找不到这个文件"。
- **键盘**：可以聚焦；↩ 打开，菜单键或 ⇧F10 打开右键菜单。
- **选中拷贝**：选中一段含标签的文字时，拷贝出来的是标签上的字。

### 4.2 左键

主进程按顺序判断（`openFile(path, { line })`）：

1. 再查一次。不存在了：提示"找不到 X，可能已被移动或删除"。
2. **文件夹**：在访达中打开。`.app` 这类包（看起来是文件夹，打开就会运行）改为在访达中显示。
3. **文件**：
   - 设了默认编辑器，而且这是文本文件：用编辑器打开，有行号就跳到那一行；
   - 否则用系统默认应用打开；
   - 一打开就会运行的文件（§4.4）例外：只在访达中显示，并提示"X 打开就会运行，已在访达中显示"。
   - 文本文件的判断：前 8 KB 里没有零字节。

### 4.2.1 HTML 文件（DD-156）

对话里的 HTML 文件大多是交付的成果，看的人要的是页面。文件标签和文件卡片（普通对话、Bot 的消息、输入框附的文件）走同一条规则：

| 从哪里点 | 左键 | 右键多出来的一项 |
|---|---|---|
| 文件标签、文件卡片 | 在会话的内置浏览器打开页面 | 查看源码 |
| 指向行号的文件标签（`index.html:42`） | 在文件面板看源码，跳到那一行 | 在内置浏览器中预览 |
| 文件面板的标签、目录树、工具步骤行 | 不变，看的是源码 | 在内置浏览器中预览；文件面板的工具栏还有一个地球按钮，先存盘再打开 |

- **主进程再查一次**：页面只传路径。主进程确认它是存在的 `.html` 或 `.htm` 文件，再把路径转成 `file:` 地址（`browser-open-file`），所以空格、中文和 `#` 都能正确打开。
- **同一个文件复用标签页，并且重新加载**：Bot 改完再发一版时，点开看到的是磁盘上的最新内容。网页链接仍然只切到已有的标签页（DD-85）。
- **页面的权限不变**：脚本照常运行，`fetch` 和 iframe 都读不到别的本地文件（browser-design D-196），和网页一样不能碰应用。这靠打包时关掉的 `GrantFileProtocolExtraPrivileges` 熔断开关（`build-app.mjs`）：开发版的 Electron 没关，页面能读到本机文件，所以来路不明的 HTML 不要在开发版里点开。端到端测试 `content-actions.mjs` 在打包版上检查这一点。
- **模型接管这个标签页之后**：内核按 D-196 检查。工作区外的文件在重新加载时会回到空白页，工作区内的不受影响。
- **没有内置浏览器时**：网页版预览里看源码；不在会话里（新会话页的输入框）时交给系统默认应用，和其他文件一样。

### 4.3 打开方式与编辑器

- **默认打开方式**：
  - 起初是"系统默认应用"；
  - 在右键的"打开方式"里选了某个编辑器，就用它打开，并记住它：以后左键点文本文件都用它；
  - 选"系统默认应用"就恢复。
  - 记在应用的偏好里（`openWith`，编辑器的 Bundle ID）。这是界面的偏好，不进 finx 的配置。记住的编辑器卸载了，当作没设。
- **找编辑器**（macOS）：
  - 用一次 Spotlight 查询，按已知编辑器的 Bundle ID 找；
  - 找到的显示应用自己的名字和图标；
  - 结果在应用运行期间缓存。打开菜单时，如果距上次查找超过一分钟，就在后台重查，下次菜单用新结果。
- **跳到行号**，按编辑器的家族：

| 家族 | 编辑器 | 怎么打开 |
|---|---|---|
| VS Code 系 | VS Code、VS Code Insiders、VSCodium、Cursor、Windsurf、Trae、Qoder、Kiro | `<协议>://file<路径>:<行>:1`；协议名读应用里 `product.json` 的 `urlProtocol` |
| JetBrains | IntelliJ IDEA、WebStorm、PyCharm、GoLand、RustRover、CLion、PhpStorm、Rider、Android Studio | `open -na <应用> --args --line <行> <路径>` |
| Xcode | Xcode | `xed --line <行> <路径>`；失败时退回 `open -a` |
| 自带命令行 | Zed、Sublime Text | 应用包里的命令行程序，参数 `<路径>:<行>` |
| 其他 | BBEdit、Nova、TextMate、CotEditor、Typora、文本编辑 | `open -a <应用> <路径>`，不跳行 |

- 所有调用都用参数数组（`execFile`），不拼 shell 字符串；路径和行号不经过 shell。
- Windows、Linux 这一期只有"系统默认应用"（DQ-40）。

### 4.4 一打开就会运行的文件

有些文件交给系统默认应用，就等于运行它：
- 应用和安装包：`.app`、`.pkg`、`.mpkg`、`.mobileconfig`、`.prefPane`、`.saver`、`.kext`；
- 可执行文件：`.command`、`.tool`、`.terminal`、`.workflow`、`.action`、`.jar`；
- 脚本：`.scpt`、`.scptd`、`.applescript`、`.sh`、`.zsh`、`.bash`、`.py`（macOS 默认用 Python Launcher 打开就是运行）、`.rb`、`.pl`；
- 网址文件（打开就跳转）：`.webloc`、`.inetloc`、`.fileloc`、`.url`；
- Windows：`.exe`、`.bat`、`.cmd`、`.com`、`.ps1`、`.msi`、`.lnk`、`.scr`、`.vbs`、`.js`、`.wsf`、`.hta`；
- Linux：`.desktop`、`.AppImage`、`.run`；
- 有执行权限的文件。

这些文件：
- 用默认应用打开时，一律只在访达中显示，明确选"系统默认应用"也一样。真要运行，在访达里双击；
- 文本类的（脚本）设了编辑器时照常用编辑器打开，那只是查看。

这样，就算有人通过网页内容诱导模型写出"[查看报告](~/Downloads/x.command)"，点一下也不会运行任何东西。

## 5. 网页链接

### 5.1 样子

- 文字仍是链接色，悬停加下划线，和现在一样。
- 前面加一个 14 像素的图标：
  - 本机地址（`localhost`、`127.x`、`[::1]`、`*.localhost`）：电脑图标；
  - https 网站：缓存里有它的图标就用，没有就是地球图标。
- **站点图标只读缓存**：
  - 用 `browser/site_icon { origin, cached: true }`，渲染时不联网（G3）；
  - 原因：如果回复里出现链接就去取图标，模型（可能被网页内容带偏）只要写一个链接，就能让你的电脑去访问那个地址，不用你点。回复里不加载图片，也是这个原因；
  - 缓存来自你在内置浏览器里打开过的网站、网站权限、搜索引擎。在内置浏览器里打开一次，以后它的链接就有图标了。
- **裸网址**（链接文字就是网址本身）：
  - 去掉 `https://`、`www.` 和末尾的 `/`；
  - 超过 60 个字符时中间省略，保留域名和最后一段；
  - 域名取自网址解析的结果，所以 `https://example.com@evil.com` 显示成 `evil.com`；
  - 悬停显示完整网址。

### 5.2 左键

- **左键**：在当前会话的内置浏览器里打开。
  - 这个会话已经有标签页在同一个地址上，就切到它，否则新开一个标签页；
  - 浏览器面板没开就打开它，对话照样在左边。
- **⌘ + 左键**（Windows、Linux 上是 Ctrl）**或中键**：在系统默认浏览器打开。
- **不在会话里的地方**：用默认浏览器打开。
- **面板是你自己的**：内置浏览器面板不受"允许 FinxWork 控制浏览器"的开关影响，那个开关只管智能体的浏览器工具。从链接打开的页面，和你在面板里自己开的标签页一样，智能体下次用浏览器时能看到它（browser-design §7.4）。

### 5.3 右键菜单

```
在内置浏览器中打开          （不在会话里时没有这一项）
在 Chrome 中打开            （系统默认浏览器的名字；不知道名字时是"在默认浏览器中打开"）
─────────
拷贝链接
```

### 5.4 主进程

- 用默认浏览器打开：放行 http 和 https（原来只有 https 和本机的 http），其他协议仍然不开。主窗口打开新窗口的处理也一样。
- 新增"在会话的内置浏览器里打开"：
  - 只收 http、https；
  - 同一会话里地址相同的标签页（忽略末尾的 `/`）就切过去，没有就新开一个，标签页属于这个会话；
  - 打开后，页面把浏览器面板显示出来。

## 6. 代码块

### 6.1 标题栏

- 代码块顶部一条 30 像素的标题栏，下面是代码，整体仍是原来的圆角框。
- **左边**：语言名，按围栏里写的显示。命令块前面加终端图标。没写语言的代码块，左边空着。
- **右边**：按钮，图标加文字，次要文字色，悬停变主文字色并加底色：
  - **拷贝**：所有代码块都有，点了变成 ✓ 一秒半，和消息的拷贝一样；
  - **在终端中打开**：只有命令块有（§6.2）。
- **生成中的代码块**：有标题栏和语言名，没有按钮（§3.5）。写完再出现，位置不跳。
- **含看不见的字符**：代码里有控制字符或双向文本控制符（U+202A–202E、U+2066–2069）时，标题栏里多一个橙色的"含隐藏字符"，悬停说明"这段代码里有看不见的字符，粘贴前请检查"。拷贝仍是原文，不悄悄删字（G4）。

### 6.2 命令块

- **哪些算**：语言名是 `bash`、`sh`、`zsh`、`shell`、`shellscript`、`console`、`terminal`、`fish`、`ksh`、`csh`、`tcsh`、`powershell`、`pwsh`、`ps1`、`cmd`、`bat`、`batch`。只看语言名，不猜内容。Python 之类的代码块只能拷贝。
- **在终端中打开**：
  - 在会话的项目目录打开一个系统终端窗口（现有的"在终端中打开"），同时把命令拷贝好，提示"已拷贝命令，粘贴到终端里运行"；
  - 不替你按回车，也不往终端里写字。运行是你在终端里的动作；
  - 真正的"运行"按钮要有应用内终端，放到下一期（§11）。
- **拷贝的内容**：围栏里的原文，去掉末尾的换行。不去 `$` 提示符：去了就和显示的不一样了。提示词让模型别加（§9.1）。

## 7. 工具步骤行与选中的文字

### 7.1 工具步骤行

- **左键不变**：展开或收起输出。
- **读取、编辑类的步骤**（类别是 `read`、`edit`，参数里有 `path`）：
  - 右键是文件的菜单（§4.5），路径按会话目录解析；
  - 读取带 `offset` 时，就是"打开"要跳到的行；
  - 打开菜单时才查存在性，不在渲染时查，因为步骤行很多。
- **运行命令的步骤**（类别是 `execute`）：

```
拷贝命令
拷贝输出                 （有输出时）
─────────
在终端中打开             （在项目目录打开终端，并拷贝命令）
```

- **其他步骤**：没有自己的菜单。

### 7.2 选中的文字

- 在对话里选中文字后右键，菜单是"拷贝"。
- 在文件标签、链接、代码块、步骤行上右键时，如果对话里有选中的文字，"拷贝"排在最前面，下面一条分割线，再接这个对象自己的菜单。
- 没有选中、也不在这些对象上时，没有菜单（和现在一样）。

## 8. 菜单

- **右键菜单用系统原生菜单**，和会话列表的右键一致（desktop-design §5.3）。
  - 原生菜单要能带子菜单（"打开方式 ›"）和图标（编辑器的图标），`popupMenu` 的菜单项加 `submenu` 和 `icon` 两个字段。
- **代码块标题栏的按钮**用应用内的样式（`.tb` 一类），不弹菜单。
- **拷贝之后的提示**：
  - 按钮：自己变成 ✓；
  - 菜单：底部弹出提示条，比如"已拷贝路径""已拷贝链接""已拷贝"。

## 9. 内核改动

### 9.1 桌面会话的格式约定（D-250）

桌面应用连着时开始的会话，系统提示词在基础提示词后面多一段固定的话：

```
In the FinxWork app, where the user reads your replies:
- Link files in Markdown, with the path relative to cwd as the target and :line when it helps: [prompt.rs](src/prompt.rs:11).
- Give each command the user may run its own ```bash block, with no $ prompt and no output in it.
```

- **为什么要加**：
  - 链接让文件有一个读得懂的名字，不用把长路径塞进句子；
  - 行号写在固定的位置，程序能准确取到；
  - 没有 `$` 的命令，拷贝出来就能直接用。
- **不加会怎样**：行内代码里的路径照样能认出来（§3.3），只是没有可读的名字；命令里的 `$` 会被一起拷走。
- **不说的**：
  - 不提"运行按钮"，因为没有；
  - 不提网址的写法，模型本来就写完整网址。
- **怎么判断是桌面会话**：
  - 沿用"桌面应用连着"的信号（`browser_pool.has_host()`），内置浏览器默认开、电脑操控默认开用的也是它；
  - 命令行（`finx exec`）和其他客户端不加；
  - 提示词在会话开始时定下。所以在命令行里开始、后来在桌面端打开的会话没有这一段，内容区照样能用。
- **缓存**：这段是固定文字，放在基础提示词之后、工具守则之前，不影响前缀缓存。
- **自定义系统提示词**（`system_prompt_file`）照样加：这一段说的是界面怎么显示，和环境信息一样，不属于人设。

### 9.2 站点图标只读缓存（D-251）

- `browser/site_icon` 的参数加 `cached?: bool`，默认 false。
- 为 true 时：
  - 只给 `~/.finx/browser/icons` 里已经存着的图标，过期的也给；
  - 不去网站找，也不在后台重找。
- 内容区的链接用 `cached: true`，其他地方不变。

## 10. 主进程与桥接

### 10.1 新增和改动的桥接方法

| 方法 | 作用 |
|---|---|
| `pathInfo(base, paths)` | 一批路径：绝对路径、在项目里时的相对路径、是文件、文件夹还是不存在 |
| `openFile(path, { line?, app? })` | 按 §4.2 打开；`app` 是"系统默认应用"或某个编辑器。结果说明是怎么打开的，或者为什么没打开（不存在、失败） |
| `editors()` | 本机的编辑器：ID、名字、图标 |
| `openURL(session, url)` | 在会话的内置浏览器里打开 |
| `openExternal(url)` | 放行 http |
| `popupMenu(items)` | 菜单项加 `submenu`、`icon` |
| `getPreferences` / `setPreferences` | 加 `openWith` |

### 10.2 主进程把关

- 只接受自己页面发来的调用（现有的 `trusted`）。
- 路径必须是绝对路径；动手前重新 `stat`，不信页面给的结果。
- 编辑器只能是检测到的那几个，按 ID 对上。
- 网址只收 http、https。
- 不拼 shell 字符串，全部用参数数组。

### 10.3 端到端测试的两个口子

原生菜单和系统应用没法用 DevTools 驱动，所以开两个只在测试里用的口子。不设环境变量时完全不起作用，和现有的 `FINXWORK_NO_BROWSER` 同一类。

- **`FINXWORK_E2E_OPENED=<文件>`**：所有"在应用外打开"的动作（默认浏览器、默认应用、编辑器、访达、终端）不真的执行，改为往这个文件里追加一行记录。
- **`FINXWORK_E2E_MENU=<目录>`**：右键菜单不真的弹出，把菜单项写进目录里的 `shown.jsonl`；如果目录里有 `pick` 文件，就按里面的菜单项 ID 当作选中，然后删掉这个文件。

### 16.2 和方案不同的地方

- **文件标签是行内元素**（不是行内块），整个标签不折行。行内块两边总能断行，后面的"、""，"会被挤到下一行开头；行内元素两边按文字的规则断行，标点跟着标签走。代价是名字太长时不省略。
- **链接的图标和文字的前 12 个字连在一起**，不在中间断行，行尾不会只剩一个图标。
- **编辑器的图标**由主进程在回答 `editors()` 时画（Quick Look 画应用自己的图标），每个应用只画一次；检测本身不碰 Electron，可以单独测。
- **选中文字的菜单**不在输入框和文本框里出现：那里该有剪切、粘贴的编辑菜单，这一期不做。
