## 方案摘要

- **要做两件事**：
  1. 输入框的"+"菜单加"连接器"二级菜单：上面是"浏览连接器""管理连接器"，一条分割线，下面是已有的连接器，每个右边一个开关；
  2. 浏览器和桌面控制进入连接器体系，设置页里藏着的入口搬到用户每天看得到的地方。
- **两个浏览器并存**：
  - **内置浏览器**：FinxWork 自带，独立的登录状态。桌面端默认开，不是连接器，没有连接器开关；想关在"设置 › 浏览器"里关；
  - **你的浏览器**（Chrome、Edge、Brave）：系统连接器。连接流程就是现有的扩展引导，连接器的开关只管它；
  - 开了你的浏览器，内置浏览器照样用，两者分工。
- **怎么选**：
  - 默认用内置浏览器：本地页面、文件、不需要登录的网页；
  - 需要你的登录状态，或者你点名要用你的浏览器时，才用你的浏览器；
  - 在你的浏览器里第一次打开一个网站，一定先问你，绕过权限也一样。这一步就是同意的环节，所以不会悄悄用你的账号；
  - 你的浏览器没连上时，智能体说明情况，不会自己换到内置浏览器去登录；
  - 不做"首选浏览器"设置（§3.3）。
- **桌面控制**：也是系统连接器，连接流程是授予系统权限。
- **一个全局开关**：
  - 输入框菜单、"我的"列表、详情页里的开关是同一个，写用户配置；
  - MCP 连接器照旧，新对话起生效；
  - 系统连接器对已经打开的对话也立即生效，在它们各自的下一次模型请求之前（D-224）。
- **内核**：
  - 浏览器工具还是一套。你的浏览器开着时，`browser_navigate` 多一个参数，选在哪个浏览器里开新标签页；之后的操作跟着标签页走；
  - "真实登录，绕过权限也要问"从按配置判断改成按标签页判断；
  - 系统连接器的工具按配置增减，配置变化推到打开的对话；
  - 中途加入的工具，它们的使用规则单独追加进系统提示词；
  - MCP 不变；协议只给审批事件加了一个可选字段 `own_browser`（§3.4）。
- **代价**：
  - 内置浏览器默认开，每个对话的每次请求都多带浏览器的 8 个工具定义，大多能命中缓存；不浏览网页的人也要付出这部分；
  - 开关一次，之后每个还在继续的对话，下一次请求的缓存整个失效一次。
- **工作量**：约 8 天（§10）。

## 1. 现状

- **"+"菜单**只有"添加文件和图片"和"添加文件夹"（`composer/Composer.tsx` 的 `PlusMenu`）。菜单组件里已经有悬停展开的二级菜单 `SubMenuItem`，模型选择在用，但它还不支持图标。
- **连接器**：
  - 在"自定义 › 连接器"里管理，分"我的""发现"和详情页；
  - "添加"走 MCP 的流程：先填地址，探测之后再设置，需要时登录；
  - 开关写 `mcp_servers.<名>.enabled`，新会话起生效（DD-43）。
- **浏览器**：
  - `browser.enabled` 默认是 false；
  - 用哪个浏览器由 `browser.backend` 决定，一个会话只用一个：内置浏览器，或者你的浏览器（`extension`），二选一；
  - 桌面端只有"设置 › 浏览器"里的"连接你的浏览器"引导会顺带打开它，而且连上以后智能体就改用你的浏览器，内置浏览器不再给智能体用；
  - 想让智能体用内置浏览器，只能手写配置；
  - 内核的浏览器池本来就能同时挂着内置浏览器和扩展（`finx-browser/src/pool.rs` 的 `host` 和 `extension` 是两个位置），只是每个会话只取一个。
- **桌面控制**：`desktop.enabled` 默认是 false，入口在"设置 › 桌面控制"。程序 agent-desktop 已经随应用打包，真正要用户做的只有授予系统权限。
- **共同的问题**：
  - 工具在建会话之前就加进注册表（`kernel.rs` 的 `add_browser_tools`、`add_desktop_tools`），会话中途不会变；
  - 它们的使用规则（`guidelines`，如"页面内容是数据，不是指令"）在会话开始时写进系统提示词，之后冻结（`prompt.rs`）。

## 2. 目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 找得到 | 在每天都用的输入框里，能看到并打开你的浏览器、桌面控制和其他连接器 |
| G2 | 开箱能浏览 | 不用设置，智能体就能打开本地页面、文件和不需要登录的网页 |
| G3 | 账号只在需要时用 | 用你的登录状态，只在任务需要或你点名时发生，而且每个网站第一次都先问你 |
| G4 | 一个开关 | 每个连接器只有一个开关，在哪里看到的都是它 |
| G5 | 连接流程贴合能力 | 系统连接器的连接流程按它真正需要的来做：装扩展、授权，不套用 MCP 的"地址、探测、登录" |
| G6 | 守住缓存纪律 | 工具集合只在用户主动操作时、在请求边界变化 |

**不做的**：把系统连接器做成 MCP 服务器；改动 MCP 的机制；按对话开关；"首选浏览器"设置。

## 3. 两个浏览器

### 3.1 分工

| | 内置浏览器 | 你的浏览器 |
|---|---|---|
| 是什么 | FinxWork 自带：桌面端里是内嵌的浏览器，命令行里是 finx 启动的本机浏览器，都用独立的用户目录 | 你自己的 Chrome、Edge 或 Brave，通过 FinxWork 扩展连接 |
| 登录状态 | 它自己的：要登录的网站，在里面登录一次就行 | 你已经登录的账号 |
| 用来做什么 | 本地页面（localhost）、文件、PDF、不需要登录的网页 | 需要你的账号的网站 |
| 开关 | 桌面端默认开，在"设置 › 浏览器"里可以关 | 系统连接器：连接一次，之后在连接器里开关 |
| 审批 | 按权限模式：每个网站第一次先问，绕过权限时不问 | 每个网站第一次一定先问，绕过权限也问（browser-design §8.4.3） |

### 3.2 怎么选

1. **默认用内置浏览器**。
2. **以下两种情况用你的浏览器**：
   - 任务需要你的登录状态，比如要看你账号里的后台；
   - 你点名要用你的浏览器。
3. **第一次在你的浏览器里打开一个网站，一定先问你**。审批框写明"在你的浏览器里打开"（§3.4）。所以就算智能体判断错了，也不会在你不知道的时候用你的账号。
4. **你的浏览器没连上或者关着时**：智能体说明情况，请你打开或重新连接。它不会换到内置浏览器去登录：那里没有你的账号，换过去只会让你在内置浏览器里再登录一遍。
5. **怎么告诉模型**：只在 `browser_navigate` 的 `browser` 参数说明里写一句，不加进系统提示词（§9.2）。

### 3.3 为什么不做"首选浏览器"

- 首选是你的浏览器时，本地预览、普通网页也都会用你的账号打开：多用了账号，什么也没换来；
- 首选是内置浏览器时，要登录的网站又得每次点名。按"需不需要你的账号"分工，本来就不需要这个设置；
- 主流产品里，内置浏览器和用户自己的浏览器一般并存分工，只有个别产品另设了"首选浏览器"。

### 3.4 审批里写明是哪个浏览器

- **你的浏览器**：标题是"在你的浏览器里打开 dash.cloudflare.com？"，下面一行"用的是你已经登录的账号"；
- **内置浏览器**：沿用现在的"允许 finx 使用 dash.cloudflare.com？"；
- 绕过权限模式下仍然询问时，那一行说明改成"用的是你已经登录的账号，所以绕过权限也会先问你"；
- 内核在 `approval_requested`（和重连时补发的待审批项）里带上 `own_browser`，桌面端据此显示。从参数里读不出来：操作已有标签页的调用没有 `browser` 参数，只开着你的浏览器时也没有；"落在哪个浏览器"只有内核按标签页判断得出。

## 4. 系统连接器

> v0.6：桌面控制已移出连接器，见 computer-use-design.md。下面写到桌面控制的地方只作记录。

### 4.1 和 MCP 连接器的区别

| | MCP 连接器 | 系统连接器 |
|---|---|---|
| 有哪些 | 用户添加的 | finx 自带：你的浏览器、桌面控制 |
| 怎么出现 | 添加之后才在"我的"里 | 一直在"我的"里（"系统"一组），连接之前显示"连接"按钮 |
| 第一次 | 添加：地址 → 探测 → 设置 → 登录 | 连接：各有自己的流程（§6） |
| 之后 | 开关、编辑配置、删除 | 开关、它自己的设置；不能删除 |
| 工具怎么给模型 | 默认按需加载（mcp-design §7） | 直接进工具列表 |
| 审批 | 不审批（D-107） | 你的浏览器按网站（browser-design §7）；桌面控制按应用（`[desktop.apps]`） |
| 开关 | `mcp_servers.<名>.enabled` | `browser.extension`、`desktop.enabled` |
| 生效 | 新对话（不变） | 建议包括已经打开的对话（§5.2） |

内置浏览器不在这张表里：它和读文件、运行命令一样，是 finx 本来就有的能力，不是连接进来的东西。

### 4.2 为什么不改成 MCP 服务器

- **审批会变粗**：浏览器按每次调用算出"在哪个网站上做什么"，私有网络要单独授权，执行前还要核对页面没有变（browser-design §7）。MCP 调用不审批，只能整个放行或不放行。
- **多一层转换**：页面、标签页和 ref 都在会话里；内置浏览器和扩展各走 finx 自己的协议。中间再隔一层 MCP，每一步都多一次编解码。
- **加载方式不合适**：浏览器一用就是连续很多步，工具适合直接进工具列表；MCP 默认按需加载，每次都要先搜索一轮。

### 4.3 状态

| 连接器 | 状态 | 来源 |
|---|---|---|
| 你的浏览器 | 未连接；可用 · Google Chrome；浏览器没有打开；扩展没连上；需要更新 | 用户配置、`browser/status` |
| 桌面控制 | 未连接；可用；未安装（找不到 agent-desktop）；需要授权（没有辅助功能权限）；这台电脑不支持 | 用户配置、桌面端读到的程序和系统权限 |

- **"已连接"的判断**：用户配置里有 `browser.extension`（或 `desktop.enabled`）这一项，不论真假。连接流程写下它，之后的开关只改它的值。
- **出状况时**：只在需要处理时显示状态，点状态进入修复（重新连接、打开系统设置）。

## 5. 全局开关与生效时机

### 5.1 一个开关

- 输入框菜单、"我的"列表、详情页里的开关是同一个，写用户配置：
  - 你的浏览器：`browser.extension`；
  - 桌面控制：`desktop.enabled`；
  - MCP 连接器：`mcp_servers.<名>.enabled`，与现在相同。
- 内置浏览器的开关只在"设置 › 浏览器"里：`browser.enabled`。
- 项目只能收紧（D-178）：项目配置关掉了的，开关仍然写用户配置，并照现在的做法提示"已打开 X，但 <文件> 又关掉了它"。

### 5.2 什么时候生效

| 开关 | 生效 | 理由 |
|---|---|---|
| MCP 连接器 | 新对话起生效，不变 | 用户的决定：MCP 不动 |
| 你的浏览器、桌面控制、内置浏览器 | 所有对话，各自在下一次模型请求之前生效 | 见下 |

- **为什么要对打开的对话生效**：典型的场景是，对话里智能体说需要你的登录状态，用户在"+ › 连接器"里打开你的浏览器。只对新对话生效的话，这个对话还是用不了。"全局"的本意，就是现在所有对话都按它来。
- **代价**：开关之后，每个还在继续的对话，下一次请求的缓存整个失效一次。空闲的对话不付出任何代价，直到它再次发出请求。
- **没有采用的做法**：也只对新对话生效。内核这部分不用改，但打开时只能提示"新对话起可用"，用户需要另开一个对话。
- **提示**：
  - 系统连接器：如"已打开你的浏览器，所有对话从下一步起可以用它"；
  - MCP 连接器：沿用现有的提示，如"已启用 GitHub，新会话起可用"。

## 6. 连接流程

每个系统连接器的"连接"打开它自己的设置页（sheet），不走 MCP 的添加流程。在"我的"、"发现"、详情页和输入框菜单里点"连接"，打开的都是同一个；在输入框里点，就地打开，不离开对话。

### 6.1 你的浏览器

就是现有的连接引导（`BrowserSettings.tsx` 的 `Guide`），整个搬过来：

1. **选浏览器**：列出这台 Mac 上找到的 Chrome、Edge、Brave。一个都没有时，给出"下载 Chrome"；
2. **准备**：注册宿主、复制扩展；
3. **添加扩展**：在浏览器里添加 FinxWork 扩展，只需要做一次；
4. **等扩展连上**；
5. **完成**：写 `browser.extension = true`。

以后换一个浏览器，在详情页的 ⋯ 里选"更换浏览器"，走同一个引导。扩展没连上、浏览器没有打开、版本对不上时，状态写明，点进去重新连接（引导现有的这些分支都保留）。

### 6.2 桌面控制

```
┌──────────────────── 连接桌面控制 ────────────────────┐
│ 让 finx 查看和操作这台 Mac 上的其他应用。            │
│ 每个应用第一次用到时会先问你；发消息、付款、删除前   │
│ 也会先停下来问你。                                   │
│                                                      │
│ 辅助功能   必需，读取窗口并点击、输入   [打开系统设置] │
│ 屏幕录制   可选，给窗口截图时需要       [打开系统设置] │
│                                                      │
│                                 [取消]  [完成]       │
└──────────────────────────────────────────────────────┘
```

1. **授权**：
   - 每一行显示"已授权"或"打开系统设置"；
   - 回到应用时自动刷新状态，沿用"设置 › 桌面控制"现有的做法；
   - 写明"权限刚打开时，可能需要重启 FinxWork 才生效"。
2. **完成**：辅助功能授权之后才能点，写 `desktop.enabled = true`。
3. **找不到 agent-desktop**：只在开发版里可能出现，沿用现有的"未安装"一行。
4. **不是 macOS**：连接器显示"这台电脑不支持"，不能连接。
5. **出状况**：权限被收回时显示"需要授权"，点进去回到这一页。

## 7. 输入框的"+"菜单

### 7.1 结构

```
┌──────────────────────────┐
│ 📎 添加文件和图片    ⌘U │
│ 📁 添加文件夹            │
│ ──────────────────────── │      ┌──────────────────────────────────┐
│ 🔌 连接器          5  ›  │ ───▶ │ 🔍 浏览连接器                    │
└──────────────────────────┘      │ ⚙️ 管理连接器                    │
                                  │ ──────────────────────────────── │
                                  │ 🌐 你的浏览器                ●── │
                                  │ 💻 桌面控制                [连接] │
                                  │ G  GitHub                    ●── │
                                  │ H  hermesh       需要登录    ──○ │
                                  └──────────────────────────────────┘
```

- **一级菜单**：添加文件和图片、添加文件夹，分割线，然后是"连接器"。"连接器"右边显示开着几个，再加 ›。
- **二级菜单**：悬停或按 → 展开。复用 `SubMenuItem`，给它加上图标。
  - **浏览连接器**：进入"自定义 › 连接器 › 发现"；
  - **管理连接器**：进入"自定义 › 连接器 › 我的"；
  - 分割线；
  - **连接器列表**：系统连接器在前（你的浏览器、桌面控制），MCP 连接器按名字排。与"我的"列表相同，两个系统连接器总在，所以列表不会是空的。内置浏览器不在这里。
- **每一行**：

## 9. 内核改动

MCP 不变。协议只加一个可选字段：`approval_requested` 和待审批项（`PendingApproval`）的 `own_browser`（§3.4）。

### 9.1 配置

| 配置项 | 含义 | 默认 |
|---|---|---|
| `browser.enabled` | 内置浏览器 | 不写时为"自动"：桌面端连着时开，命令行里关（命令行没有内嵌浏览器，要另外启动本机浏览器） |
| `browser.backend` | 内置浏览器用哪种：`auto`、`embedded`、`managed` | `auto`，不变 |
| `browser.extension` | 你的浏览器（新增） | 不写时为关 |

- **旧配置**：`backend = "extension"` 读作 `extension = true`、`backend = "auto"`。桌面端下次写浏览器设置时顺手改成新写法。

### 9.2 一个会话里的两个浏览器

- **工具还是一套**：
  - 两个浏览器都开着时，`browser_navigate` 和 `browser_tabs`（开新标签页时）多一个参数 `browser`：`builtin`（默认）或 `yours`；
  - 只开着一个时没有这个参数，工具定义和现在一样；新页面开在开着的那个里。
- **参数说明只写一句**：内置浏览器有它自己的登录状态，用于本地页面、文件和不需要账号的网站；只有任务需要用户的账号或用户点名时，才用 `yours`；在那里每个网站第一次都会先问用户。
- **标签页属于打开它的浏览器**：
  - 之后的读取、操作、截图都跟着标签页走；后退、前进、刷新作用在当前标签页所在的浏览器；
  - 你的浏览器里的标签页和 ref 以 `y` 开头（`y2`、`ye14`），两个浏览器的编号不会撞上，看编号就知道在哪个浏览器；
  - `browser_tabs` 分两段列出两个浏览器里的标签页。
- **两个租约**：会话的 `BrowserHandle` 最多持有两个浏览器的租约，第一次用到哪个才去取哪个。浏览器池本来就分别挂着两个，不用改。
- **真实登录按标签页判断**：
  - 现在"绕过权限也要问"按配置判断（`SitePolicy.real_logins`）；
  - 改为按这次调用落在哪个浏览器：新开标签页看 `browser` 参数，其余看标签页属于谁；
  - 网站权限（`browser.sites`）两个浏览器共用。
- **你的浏览器不可用时**：
  - 连接器关着时，没有 `browser` 参数，模型用不到它；
  - 开着但扩展没连上时，调用返回错误，说明需要用户在 FinxWork 里重新连接。不自动换成内置浏览器。

### 9.3 工具按配置增减

- **现在**：建会话之前，浏览器和桌面控制的工具就加进 `deps.tools`，整棵智能体树共用。
- **改为**：
  - 基础注册表里没有它们；
  - 会话的注册表 = 基础 + 开着的浏览器工具（任一浏览器开着就有）+ 开着的桌面控制工具 + MCP 部分；
  - 组合相同的会话仍然共用同一份注册表（`extended` 按种类缓存，现在就是这样做的）。

### 9.4 推到打开的对话（D-224）

- **发现变化**：服务本来就监视配置文件（`finx-server/src/customize.rs` 的 `config_changed`）。变化之后，对每个打开的根会话，按它的工作区重新合并配置，比较 `[browser]` 和 `[desktop]` 中与它有关的部分。
- **生效时机**：在这个会话的下一次模型请求之前，也就是 mcp-design §5.4 的那个检查点（插话和待生效的模型切换也在那里处理）：
  - **工具**：加上或去掉浏览器、桌面控制的工具，以及 `browser_navigate` 的 `browser` 参数、随 `script_enabled` 增减的 `browser_eval`；
  - **句柄**：创建或释放会话的 `BrowserHandle`、`DesktopHandle`。关掉一个浏览器，关掉这个对话在那个浏览器里打开的标签页；
  - **权限**：换上新的网站策略和应用权限。权限不在提示词里，单独改它们没有缓存代价。所以收回"所有网站"后，打开的对话从下一步起就不再放行；
  - **使用规则**：基础提示词在会话开始时冻结，里面只有当时那些工具的使用规则。中途加入的工具，它们的规则放进系统提示词末尾单独的一段，与 MCP 段的做法相同；
  - **记录**：工具列表或这一段确实变了，才记一条 `system_prompt` 条目。
- **不受影响的**：正在执行的工具批次。子智能体在它们的下一次请求时跟上。
- **中途去掉的工具**：它们的规则留在冻结的基础提示词里不动。那只是多几行无害的说明，删掉反而要重写前缀。

  - **浏览器**：就是"设置 › 浏览器"的第一行，写 `browser.enabled`（browser-design §10.1）；用哪个浏览器、连接你的浏览器、网站权限都在设置里；
  - **电脑操控**：就是"设置 › 电脑操控"的第一行，写 `desktop.enabled`（computer-use-design §4）。还不能用时开关是灰的，旁边写"需要授权"或"组件缺失"，点一下打开"设置 › 电脑操控"；这台电脑不支持时不显示；
  - 和连接器的开关一样，点了菜单不关，提示"所有对话从下一步起"可以用或不再用；
  - **连接器二级菜单**：只有 MCP 连接器；一个也没有时写"还没有连接器"。
  - **技能二级菜单**（2026-11-02 追加）：紧跟在"连接器"下面，右边是能用几个。里面是"浏览技能""管理技能"（进入"自定义 › 技能"的发现、我的），分割线，然后是这个对话能用的技能，也就是输入 `/` 时列出的那些，按名字排，悬停看说明。点一个就像在 `/` 菜单里选中它：在光标原来的位置插入技能标签，后面带一个空格，菜单关闭，光标回到输入框；没有光标时插到末尾。
  - **很多连接器或技能时**（两个二级菜单一样）：
    - 浏览、管理两行和分割线固定不动，下面的列表在菜单内部滚动；
    - 列表最多显示 8 行（256 px），整个二级菜单约 330 px。窗口太矮时列表跟着变矮，保证整个菜单留在窗口里，菜单本身不再出现第二条滚动条（列表高度不超过 `100vh - 140px`）。主窗口最小 720×480，这时仍然能放下 8 行；
    - 哪一侧还有内容，那一侧的边缘就渐隐 24 px：在顶部时只有底边渐隐，滚到中间两边都渐隐，到底时只有顶边渐隐。被切掉的半行看起来是"还有更多"，而不像菜单被截断；
    - 列表滚到头不会带着页面一起滚（`overscroll-behavior: contain`）；
    - 鼠标悬停到半露出的行，只移动焦点，列表不跳；用键盘 ↑↓ 移动时，焦点行和边缘始终隔开 24 px，不会落进渐隐区；
    - 名字太长时用省略号截断，悬停提示里有全名和说明；
    - 不加搜索框：要按名字找技能，在输入框里打 `/` 就能边打边筛选。
    - 验证：网页预览加 `?many` 参数，模拟内核会多出 30 个连接器和几十个技能，名字有长有短，有中文也有英文。中文名的技能不能作为 `/skill:` 提及，所以不出现在菜单里。
  - **二级菜单的方向**：跟着一级菜单。"+"菜单向上弹出，二级菜单就和它那一行底边对齐、向上展开；向下弹出的菜单仍然顶边对齐。
- **内核不变**：两个开关本来就是配置，对打开的对话立即生效（D-224）。
- **验证**：`system-browser.mjs` 在"+"菜单里关掉、打开浏览器，设置页的总开关跟着变；`computer-use.mjs` 检查"+"菜单里的电脑操控开关和它写明的缺什么，连接器菜单和"我的"里都没有这两项。
