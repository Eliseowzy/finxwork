## 方案摘要

- **你的浏览器不再只是设置里的开关，而是对话正在用的东西**：只要这个对话在里面有标签页，"环境"卡就多一行"Chrome · 3 个标签页"。没用到时，界面和以前完全一样。
- **只在需要你时打扰你**：能自动恢复的都自动恢复，任务等着，不算失败。只有必须你动手时才出卡片。
- **应用第一次有了跳到窗口外的入口，也就有了回来的路**：点这一行，Chrome 到最前，停在智能体正在用的标签页；回来用扩展图标的弹窗。
- **标签页的归属清楚了**：任务结束后标签页归你，调试提示条也收起；要清理时在 ⋯ 里全部关闭。

## 1. 环境卡里的一行（DD-98）

不做独立的卡片：环境卡本来就在说这个对话在哪里工作，加一行不增加新概念，也不多占高度。

| 状态 | 这一行写什么 | 另外 |
|---|---|---|
| 没有标签页，也没在等 | 不显示 | |
| 有标签页，任务在用 | Chrome · 3 个标签页 | 后半句有流光 |
| 有标签页，任务结束 | Chrome · 3 个标签页 | |
| 交给你处理 | Chrome · 等你处理 | 橙点 |
| 宿主断了或任务在等 | Chrome · 正在重新连接 | 流光；Chrome 没开时写"正在打开" |
| 你收回了控制 | Chrome · 已收回控制 | 右边"允许"按钮 |

- **点这一行**：`browser/reveal` 让扩展把标签页带到前面（默认是智能体最后用的那个），再由应用 `open -a` 把浏览器本身带到前面。这两步都要：`chrome.windows.update` 只管 Chrome 内部，跨应用的前置要靠系统。
- **⋯ 菜单**（悬停才出现，键盘也能到）：列出标签页，点一个就跳到它；下面是"全部关闭"。
- **断线时**：内核不知道标签页了，显示最后知道的那些。这时每 3 秒问一次浏览器是否还在运行：Chrome 真的退出了，标签页也没了，这一行就消失。
- **一个地方**：信息卡不显示时（开着面板、窗口变窄或手动关掉），这一行变成顶栏的一个按钮，等你时带橙点。只在一个地方出现。

## 2. 需要你时

### 2.1 交给你处理（DD-99）

模型调用 `browser_wait {user: "sign in to ..."}`，任务停下来。卡片放在审批的位置，因为它就是一次审批（内核沿用审批流程）。

- 第一屏：标题"需要你在 Chrome 里处理"，下面是模型写的说明；按钮"跳过这一步"和"去 Chrome"。
- 点过"去 Chrome"后：主按钮换成"我处理好了 ⌘↩"，旁边是"再去看看"。没去过时不给"我处理好了"，免得误点。
- 步骤行写"你已处理 sign in to …"。
- 从扩展弹窗也能说"我处理好了"，不用回应用。

### 2.2 任务等浏览器（DD-100）

| 时间 | 对话里 | 应用在做什么 |
|---|---|---|
| 一开始 | 工作行写"等你的浏览器连上 · 3 秒" | 修复清单和启动脚本；浏览器设置过的话，在后台启动它（`open -g -a`），之后每 20 秒再试一次 |
| 10 秒后 | 输入框上方出卡片 | 同上 |

- **卡片**：标题"Chrome 里的 FinxWork 扩展没有连上"，说明"在扩展程序页面确认它还在，而且是打开的。连上后任务自己继续，不用回来点。"，按钮"这次不用 Chrome"和"打开扩展程序页面"。应用分不清扩展是被停用了还是被删了，所以文案两种都写。
- **选中的浏览器不在，另一个连着时**：卡片写"智能体选用的浏览器没有连上，me@home.example 连着。"，主按钮"改用它"。不自动换，那可能是另一个账号。
- **为什么等 10 秒**：重连实测在 3 秒内，这段时间不该打扰。
- 连上后卡片自己消失，任务接着走，不用用户再点。

### 2.3 系统通知（DD-101）

应用不在前面时，任何对话开始等你（审批或交给你处理）都发一条系统通知，点通知打开那个对话。用户可能正看着 Chrome，任务却在等，看起来就像卡住了。

应用启动后第一次拿到对话列表时，已经在等的不算新消息。

## 3. 扩展图标的弹窗（DD-102）

一种状态，一句话，最多一个主要动作（DD-160）。版本号、重试次数这类排查信息不放这里，放在设置页的诊断里（DD-103）。弹窗打开时状态变了会自己重画，内容没变就不动。

样子和应用的菜单一样：4px 外框里是内缩的圆角行，左边一列状态图标，右边一列文字，说明和按钮都对齐文字那一列。工作中是转圈，等你是橙点，结束是对勾；停止是输入框发送按钮的实心方块，缩小了，指上去变红。

| 状态 | 第一行 | 说明 | 按钮 |
|---|---|---|---|
| 已连接，在用 | 已连接 | 无 | 无 |
| 已连接，没在用 | 没有在用 | 智能体正在用另一个浏览器或配置文件 | 改用这个浏览器 |
| 等你处理 | 有 N 件事等你 | 无 | 对话行下面的"我处理好了" |
| 正在连接，不到 10 秒 | 正在连接… | 无 | 无 |
| 正在连接，超过 10 秒 | 连不上 FinxWork | 打开 FinxWork，它会修好连接，之后这里会自己连上 | 重试 |
| 扩展后台 2 秒内没回应 | 扩展没有响应 | 重新加载扩展就能恢复，标签页不受影响 | 重新加载扩展（弹窗自己做，不经过后台） |
| FinxWork 没打开 | FinxWork 没有打开 | 打开后，智能体才能用这个浏览器 | 打开 FinxWork（由宿主启动应用） |
| 这台电脑没设置 | 这台电脑还没有设置 | 安装 FinxWork，然后在它的设置里连接你的浏览器：商店版同步到别的电脑时就是这样 | 无 |
| 扩展太旧 | 扩展需要更新 | 更新后会自动连上，标签页不受影响 | 更新扩展 |
| FinxWork 太旧 | FinxWork 需要更新 | 打开它并更新，之后会自动连上 | 打开 FinxWork |

连接正常时，下面一行一个有标签页的对话，等你的排在前面：标题和"工作中 · 3 个标签页"。点整行回到对话，运行中的对话多一个停止图标；等你批准的写明"等你在 FinxWork 里批准"，交给你处理的写出要做什么。连接不正常时不列对话：这时回到对话和停止都发不出去。

最后一行是"把这个标签页交给 FinxWork"：只对网页显示，chrome:// 这类页面调试器附加不上；有事等你时不显示。"智能体将能读取和操作这个标签页"放在悬停提示里。交出后应用来到前面，输入框上方出现"交给这个对话：页面标题"，随下一条消息一起发出；可以点 × 不交。

图标只在需要用户动手时才有标记：等你时是数字（对话数），连不上超过 10 秒时是橙色叹号，版本对不上时是红色叹号。FinxWork 没打开是正常状态，不显示叹号。

"连不上超过 10 秒"实际就是宿主程序起不来：宿主一启动就会报状态（没打开、已连接、版本不对）。最常见的原因是清单指向的启动脚本还在，脚本要执行的 finx 或它的 FINX_HOME 却没了，比如测试的临时目录留下的脚本。应用把这种清单算作坏的（不是"另一个 FinxWork 的"），启动时和每次窗口来到前面时都修好它，所以提示让用户打开 FinxWork 是真能修好的（DD-172）。

"扩展没有响应"：后台起不来或被 Chrome 停在半路时，弹窗问不到状态。以前弹窗这时是空白的，图标上还留着上次的标记；现在 2 秒没回应就显示这一行，后台晚些回应了再按真实状态重画（DD-172）。

"更新扩展"：从文件夹装入的直接重新加载，应用已经换好了文件；商店版先问商店，没有新版本时打开扩展程序页面。

## 4. 设置 › 浏览器（DD-103）

- 未连接时写明原因，按钮是当下唯一该做的一步：

  | 原因 | 说明 | 主按钮 |
  |---|---|---|
  | 浏览器没开 | Chrome 没有打开 | 打开 Chrome |
  | 宿主被拒绝 | FinxWork 刚更新，扩展正在换用新版本，几秒内会自己连上 | 打开扩展程序页面 |
  | 清单属于另一个 FinxWork | 这个浏览器连着另一个 FinxWork | 接管 |
  | 其他 | 确认扩展在、并且是打开的 | 打开扩展程序页面 |

- 同时连着两个以上时，列出每个浏览器和账号，用户选一个。
- "查看诊断信息"展开整条链路，可以拷贝（browser-design §8.4.4）。
- 引导的第 2 步写明开发者模式要保持打开（browser-design §8.4.7）。

## 5. 其他文字

- 步骤行："已访问 github.com · 你的浏览器"，不再是英文标题 "open github.com in your browser"。
- 模型从第一次结果知道：这是用户自己的浏览器，用户看得到标签页，登录状态是真的。

## 7. 测试

`apps/desktop/e2e/your-browser.mjs`：真实应用（也可以是打包好的，`FINXWORK_E2E_APP`）、真实 Chrome、真实 finx，脚本模型。全部在私有 `HOME` 里，不碰开发者自己的 Chrome。走完这些场景：

1. 清单指向不存在的文件时被修好；另一个 home 的清单不动；引导能接管。
2. 没有标签页时什么都不显示。
3. 任务打开页面：这一行出现、有流光；分组蓝色；任务结束后流光消失，分组变灰，调试器放开，标签页还在。
4. 点这一行和顶栏按钮：标签页到前面，浏览器被带到前面。
5. ⋯ 菜单开在按钮下面。
6. 交给你处理：卡片、橙点、橙色分组、系统通知；点完任务带着快照继续。
7. 宿主被杀：约 1.3 秒恢复，接着用同一个标签页。
8. 收回控制：这一行写明，模型被告知；允许后恢复。
9. Chrome 退出：任务等，后台启动，10 秒后出卡片；"这次不用"后模型收到用户的选择。
10. 从弹窗交出标签页：出现在输入框上方，随消息发出，模型被告知。
11. 从弹窗回到对话。全部关闭。设置页的诊断。
12. 第二个真实 Chrome：待命，设置页列出两个；选第二个后任务开在第二个里；它退出后不换回第一个，卡片问"改用它"，点了才换。

`FINXWORK_E2E_SHOTS=<目录>` 存下每一步的截图，`FINXWORK_E2E_THEME=light` 切浅色。

启动参数带 `--disable-backgrounding-occluded-windows`：会话事件要等下一帧才进页面（`useSession`），而窗口被别的窗口盖住时没有帧。这不丢消息（实测：窗口恢复后立刻显示），但等页面文字的测试会超时。

## 8. 决策

| 编号 | 决策 |
|---|---|
| DD-98 | 对话用到用户浏览器时在环境卡加一行，不做独立卡片；卡片不显示时移到顶栏，始终只在一个地方；点击同时用 `browser/reveal` 和 `open -a` |
| DD-99 | 交给用户的卡片放在审批的位置；去过才能说"处理好了"；扩展弹窗也能说 |
| DD-100 | 任务等浏览器时先安静修复、后台启动，10 秒后才出卡片；连上后不用再点；选中的不在时不自动换到另一个 |
| DD-101 | 应用不在前面时，对话开始等用户就发系统通知，点了打开那个对话 |
| DD-102 | 扩展有弹窗：状态、下一步、回到对话、停止、我处理好了、交出当前标签页；图标只在要用户动手时才有标记 |
| DD-103 | 设置页按未连接的原因给出唯一的下一步，并能展开诊断 |
| DD-160 | 扩展弹窗精简为一种状态一句话、最多一个主要动作；打开时自己更新；连不上超过 10 秒才算问题，图标同时显示叹号；排查信息只留在设置页 |
| DD-172 | 清单指向的启动脚本里，finx 程序或 FINX_HOME 不在了，就算坏的，应用启动时和窗口来到前面时修复；扩展后台 2 秒没回应时弹窗显示"扩展没有响应"和"重新加载扩展"，不再空白 |

## 9. 还没验证的

- **真实模型**会不会在该交给用户时调用 `browser_wait {user}`：工具说明和提示词写了，e2e 用的是脚本模型。
- **跨 macOS 桌面空间**的前置：测试里 Chrome 是无界面的，只验证了 `chrome.tabs.update` 生效和 `open -a` 被调用。
- **旧版本的过渡**：已经在跑旧扩展和旧宿主的 Chrome，装上新版后要手动刷新一次扩展，或者重启 Chrome；旧代码不会自己退出。之后的更新都是自动的。
