# CT 结构构建：普适化实施计划（v2：agent 主导 + 内核护栏）

> 状态：阶段 0 已完成（基线见文末附录），其余未实施。
> 相关：`spatial-design.md`（§9.4 扩展约束）、`crates/finx-spatial/src/{recipe,algo,mesh}.rs`、`crates/finx-core/src/spatial.rs`、`crates/finx-core/src/skills/system/medical-imaging/`（SKILL.md、`recipes/chest.json`）、`crates/finx-spatial/examples/ct_eval.rs`。
> 定位：AI 辅助普通人看懂自己的 CT，不替代医生。目标是“大体正确、绝不卡死、不对就说不对”。
> v2 相对 v1 的变化：不再把人群/扫描条件的判断写死在 Rust 和固定配方里，改为 **判断交给 agent（know-how 写在 skill），计算和护栏留在 finx**；分割模型从“最后的可选项”提前为尽早摸底。

## 0. 现状与问题

- `chest.json` 是“全局阈值 + 连通 + 形态学”的固定流水线，agent 拿到胸部 CT 就原样跑它。
- 真实片 47083958（成人螺旋 CT 平扫，512×512×262）上气道阈值渗进肺，海绵状掩膜让网格生成卡死十几分钟。已止血（体积封顶、面数封顶、进度），但气道仍 401 mL（合理约 30–150 mL）。
- 基线（附录）又暴露：扫描范围不全时双肺整个丢失；造影片骨骼被污染。
- 根因有两层：
  1. **算子层**：阈值没有“这是不是渗漏”的判断；结果错了也照样出网格，没有自检。
  2. **决策层**：固定配方无法适应没见过的片子。我们预测不了未来传入什么 CT，也预测不了模型能力会多强，所以把判断硬编码进内核是在赌。

## 1. 架构：三层分工

| 层 | 做什么 | 谁负责 | 性质 |
|---|---|---|---|
| **快速路径** | 打开片子后跑默认配方，几十秒内出体表、肺、骨、气道 | finx | 确定性、离线、可回归 |
| **自适应** | 默认结果检查不通过，或片子类型不常见时：看片子信息 → 调整/重写配方 → 重跑 → 再检查 | agent + skill | 灵活，随模型变强自动变好 |
| **精细** | 需要肺叶、动静脉、心脏等结构时调分割模型 | agent + `spatial_script` | 可选，需下载 |

### 1.1 留在 finx 的（内核）

- **算子**：阈值、连通、形态学、区域生长、网格等，全部快、有上限、与行业无关（§9.4）。
- **护栏**：体积封顶、面数封顶、超时。任何配方（包括 agent 写出的离谱配方）都必须在上限内结束。
- **事实**：体积、直径、CT 值、直方图由内核算，agent 不看图估数。
- **检查的数值依据**：每个结构的检查结果和原因由内核算出并返回，agent 据此决策。

### 1.2 交给 agent 的（skill 里的 know-how）

- **先看再做**：读 DICOM 信息、直方图、覆盖范围，判断平扫/增强、层厚、噪声、有无金属、部位。
- **选择与调整配方**：按情况改阈值、换种子、去掉不适用的步骤，或现场拼一份新配方（腹部、头颅等没有现成配方的部位）。
- **检查 → 修正循环**：结果不合理就调整重跑，有次数上限；修不好就如实告诉用户哪个结构不可靠、为什么。
- **何时建议精细模式**。

### 1.3 原则

1. 防卡死永远由内核兜底，不依赖 agent 自觉。
2. 内核不写死胸部知识；知识以文字形式在 skill 里，改它不用发版。
3. 快速路径保留：它是首屏体验和离线兜底，也是 agent 修正的起点。
4. 每个结构都带检查，不合理就降级（标“不可靠”），绝不把明显错的结果当真给出。
5. 评测驱动，0 退步；同时评固定配方和“agent 最终交出的结果”。

## 2. 内核要补的东西

### 2.1 `spatial_build` 返回检查结果（最优先）

这是 agent 能自我修正的前提。每个结构返回：

```json
{ "id": "airway", "volume_ml": 401.4,
  "checks": [ { "check": "volume_range", "ok": false, "detail": "401 mL，预期 20–250 mL" },
              { "check": "leak", "ok": false, "detail": "在 -990 HU 仍超出上限，疑似渗入肺" } ],
  "reliable": false }
```

- 检查项是通用的（体积区间、是否碰边及碰哪一面、是否为空、是否触发封顶、连通块数、左右比），阈值由配方给（`"expect": {"volume_ml": [20, 250]}`），内核不内置“气道该多大”。
- 前端对 `reliable: false` 的结构显示“不可靠”标记。

### 2.2 给 agent 的“先看”工具

- `spatial_info` 补充：直方图与谷值、体外空气噪声 σ、扫描覆盖范围（mm）、方向与体位、是否存在 >2500 HU 的金属块、DICOM 里的造影/卷积核/层厚字段。
- 均为通用统计，不含判断；怎么解读写在 skill 里。

### 2.3 新的通用算子

| 算子 | 用途 | 说明 |
|---|---|---|
| `drop_touching_border` 支持指定面 | 修“扫描不全时整肺丢失” | 如 `{"drop_touching_border": ["left","right","anterior","posterior"]}`；头脚方向碰边不丢 |
| 带泄漏检测的生长 `grow_until_leak` | 气道等管状含气结构 | 见 §2.4 |
| 阈值取直方图谷值 | 代替写死的 -400 等常数 | `{"threshold": ["valley", -1000, -200]}` 之类 |
| 沿最窄处切分 | 左右肺粘连成一块时分开 | 通用的“最小截面切分” |
| 去噪（小核中值） | 低剂量片阈值前用 | 可选步骤 |

不做的：`normalize` 大一统步骤、造影检测、床板去除、金属处理等写死的判断逻辑。这些改由 agent 用通用算子按情况组合。

### 2.4 `grow_until_leak`（原 v1 §2 的气道算法，改为通用算子）

```json
{ "grow_until_leak": { "seed": "top_largest", "start": -950, "stop": -800,
                       "step": 10, "leak_ratio": 1.6, "max_mm3": 250000 } }
```

1. 从严阈值起逐级放宽，每级记录体积；体积比上一级突增超过 `leak_ratio` 或超过 `max_mm3`，回退到上一级。
2. 第二道：按到种子的测地距离分层成波前，单个分支的截面突增或波前碎裂即判该分支渗漏，只剪掉这一支，其余继续。
3. 返回里带 `leak_pruned`、最终阈值、分支数，进 `checks`。
4. 种子找不到（扫描不含气管顶）时返回明确原因；换种子或放弃气道由 agent 按 skill 决定。

## 3. skill 里要写的 know-how

写进 `medical-imaging/SKILL.md`（必要时拆出 `references/chest-ct.md`）。内容来自 v1 的失败模式分析，从“要实现的规则”变成“给 agent 的判断依据”。

### 3.1 流程

1. 先 `spatial_info`，判断片子类型（下表）。
2. 常规成人胸部平扫 → 直接跑默认配方；否则按下表先调配方。
3. 读每个结构的 `checks`；不通过的按 3.3 修正，最多重试 2–3 次。
4. 仍不通过 → 保留结果但标不可靠，用平实的话告诉用户原因；必要时建议精细模式。
5. 所有数值都来自内核；始终带“不能代替医生”的说明。

### 3.2 片子类型与调整

| 情况 | 怎么认 | 怎么调 |
|---|---|---|
| 造影增强 / CTA | DICOM 造影字段；主动脉、心腔 HU >150 | 骨骼阈值提高或排除纵隔中央的高密度块；血管可直接用高阈值取 |
| 低剂量 | 体外空气 σ 大（>40） | 阈值前去噪；细血管、细支气管不强求，告知细节有限 |
| 厚层（≥3mm） | 层间距 | 气道只到主支气管；小结构过滤阈值放大 |
| 儿童 | 体表尺寸、年龄字段 | 体积预期按比例缩小；气管面积阈值缩小 |
| 肺气肿 | 肺内 -950 以下占比高 | 气道生长更保守；肺体积偏大属预期，不当成错误 |
| 扫描范围不全 | 肺碰到上/下边界；覆盖范围短 | 不按头脚方向丢弃；不报总体积，只说“扫描未包含……” |
| 不含气管顶 | 顶层无圆形含气块 | 在扫描内找最上方的管状含气结构作种子；找不到就不出气道 |
| 俯卧 / 头脚倒置 | 方向矩阵 | 内核已按患者坐标处理（基线已验证），无需调整 |
| 金属植入物 | 存在 >2500 HU 块 | 单独成结构；告知周围伪影区的结果不可靠 |
| 实变、大量积液、术后单肺 | 肺体积小、左右严重不对称 | 不强行修正；如实说明，这可能就是病变本身 |
| 非胸部（腹部、头颅等） | 部位字段、解剖特征 | 现场拼配方，只做有把握的结构（体表、骨），其余建议精细模式 |

### 3.3 检查不通过时的修正手册

- 气道过大 / 渗漏 → 收紧 `stop`、降低 `leak_ratio`；仍不行只保留气管和主支气管。
- 气道过小或只有气管 → 放宽 `stop`；厚层片则接受。
- 肺为空 → 多半是碰边被丢或阈值不合适，查覆盖范围和直方图谷值。
- 只有一块肺且体积大 → 左右粘连，用最窄处切分。
- 骨骼体积异常大 → 多半是造影剂，按增强片处理。

## 4. 分割模型

- **定位**：精细层的主力，也是规则方案的**标尺**。提前到阶段 2 摸底：模型快且好，则规则只需做到“预览 + 兜底 + 校验”，不再深挖；模型走不通，才值得把规则打磨到底。
- **候选**：`lungmask`（Apache-2.0，小，肺和肺叶）优先；TotalSegmentator（代码 Apache-2.0；权重需逐任务核对许可，部分限非商用）；MONAI 模型库里许可清楚的模型。
- **运行**：agent 经 `spatial_script` + uv 调用，skill 提供脚本；首次使用征得用户同意后下载（明示大小：lungmask 数十 MB，TotalSegmentator fast 数百 MB、全量 1–1.5 GB），之后离线。结果以 labelmap 回到内核，由内核出网格和统计，并过同一套 `checks`。
- **摸底要回答的问题**：普通 Mac 上的耗时、评测集上的 Dice、安装和下载体验、许可证能否商用。

## 5. 评测（`~/ct-eval`，仿 docx-eval）

### 5.1 两种模式

| 模式 | 被测对象 | 特点 |
|---|---|---|
| **配方模式**（已有） | 固定配方 + 内核 | 确定性，快，进 CI；守住快速路径和算子不退步 |
| **agent 模式**（新增） | agent + skill + 内核，从“拿到片子”到“交出结果” | 不确定，每例跑 N 次看通过率；衡量 skill 的 know-how 是否有效 |

agent 模式的指标：最终结果的 Dice / 体积是否在区间、**“不可靠”是否标对**（真错没标是最严重的失败）、重试次数、总耗时、工具调用数。

### 5.2 数据

- **合成体模族**（已有 11 个变体，带真值）。待补：更强的低剂量噪声；肺气肿区与气道相通的变体（测渗漏）；左右肺粘连；非胸部体模。
- **公开真实数据**（只存本地，仓库只留指标，记录来源与许可）：TotalSegmentator 数据集（带参考掩膜，可算 Dice）、LIDC-IDRI、EXACT'09（气道）、增强片若干。
- **用户样本**：47083958 等，只存本地、只留指标。

### 5.3 验收

- 配方模式 0 退步：Dice 降 >0.01、体积跌出区间、耗时超上限、新增失败，任一即退步（`ct_eval diff` 退出码 1）。
- agent 模式：通过率不降；“真错未标”为 0。
- 体模子集（3–4 个变体）进 `cargo test`。

## 6. 性能

基线实测（47083958）：加载 11s，配方 36s，其中网格是大头（骨骼到 36s 才出）。agent 的检查-修正循环会多次调用 `spatial_build`，所以单次构建的速度比 v1 更重要。

| 方向 | 做法 | 目标 |
|---|---|---|
| 增量构建 | agent 只改一个结构时，只重算它和依赖它的结构，其余复用 | 修正一轮 ≤10s |
| 网格 | 按结构包围盒裁剪；在约 1mm 网格上建面再抽稀；结构间并行 | 每结构 ≤3s |
| 掩膜 | 位压缩；形态学按包围盒裁剪 | 各步快 2–5 倍 |
| 加载 | 解码并行；缓存命中直接读 | 首次 ≤10s，再次 ≤3s |
| 首屏 | 先出体表和肺，其余续出 | 首个可看结果 ≤10s |

目标：快速路径全配方 ≤20s；含 agent 修正的完整流程 ≤90s；任何单次构建硬上限 120s。

## 7. 分阶段里程碑

### 阶段 0：评测基建 —— 已完成
`ct_eval`（run/diff）、11 个体模变体、真实片基线。见附录。

### 阶段 1：内核检查 + 两个已知问题（1–2 周）
- 改：`recipe.rs` / `algo.rs`（`drop_touching_border` 指定面、`grow_until_leak`、配方 `expect` 与 `checks`）、`finx-core/src/spatial.rs`（`spatial_build` 返回 `checks` / `reliable`）、`chest.json`（用新算子、加 `expect`）、前端“不可靠”标记（`apps/desktop/src/renderer/src/spatial/`）、`ct_eval`（读 `checks`）。
- 验收：no_trachea_top / no_lung_base 体模的肺恢复（Dice ≥0.9）；47083958 气道进入 20–250 mL；配方模式其余 0 退步。
- 风险：泄漏剪枝过严只剩气管 → 用分支数指标监控。

### 阶段 2：模型摸底（约 1 周，可与阶段 1 并行）
- 改：skill 新增模型脚本与 uv 依赖、`spatial_script` 的 labelmap 回传；评测集加入带参考掩膜的公开数据。
- 产出：一份对比（模型 vs 规则：Dice、耗时、体积、许可证），以及“规则做到哪为止”的结论。
- 风险：许可证、下载体积、CPU 推理慢 → 先只试 lungmask。

### 阶段 3：agent 自适应（2–3 周）
- 改：`spatial_info` 补“先看”字段（§2.2）；SKILL.md 写入 §3 的流程、类型表、修正手册；补通用算子（谷值阈值、最窄处切分、去噪）；`ct_eval` 增加 agent 模式。
- 验收：agent 模式在体模全族上通过率 ≥90%，“真错未标”为 0；造影、厚层、扫描不全等变体由 agent 自行调整后达标或正确标不可靠。
- 风险：结果不稳定、耗时长 → 重试上限、增量构建；know-how 写得太细反而束缚模型 → 用评测决定留哪些。

### 阶段 4：性能（1–2 周，可穿插）
- 改：`mesh.rs`、`algo.rs`、`dicom.rs` / `brick.rs`、`spatial.rs`（增量构建）。
- 验收：达到 §6 目标，几何指标 0 退步。

### 阶段 5：精细模式产品化（视阶段 2 结论）
- 下载同意与存储、许可证清单、离线运行、UI 入口。

## 8. 面向专业用户的演进（现在不做，只守住口子）

- 架构可迭代：内核、配方、`spatial_script`、评测都能复用，专业版是一个更大的行业包（§9.4）。
- 现在只守一条：**掩膜是一等数据**（能存、能改、能导出），结构不只以网格存在。内核已满足。
- 以后再做：掩膜编辑工具、DICOM SEG / NIfTI 导出、随访配准、专家标注回流。
- 真正的门槛是合规（医疗器械注册）和模型许可证，需单独立项评估。

## 9. 风险汇总

- **agent 不确定性**：同一片子两次结果不同 → 快速路径保持确定；修正循环有上限；agent 模式评测看通过率。
- **agent 写出离谱配方** → 内核护栏兜底，这是硬约束。
- **罕见病例**（大量积液、全肺实变、术后单肺）→ 不追求覆盖，靠检查如实降级。
- **过拟合 47083958** → 调整以评测集整体为准。
- **数据隐私与许可** → 真实片只存本地，仓库只留指标。
- **医疗表述** → 所有结果仅供参考，UI 和 skill 保持“不替代医生”。
