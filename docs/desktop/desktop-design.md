## 1. 目标与范围

### 1.1 目标

| 编号 | 目标 | 含义 |
|---|---|---|
| G1 | 三平台一套代码 | macOS 先做，Windows、Linux 后做。三个平台用同一份界面代码、同一个渲染引擎 |
| G2 | 复用内核 | 通过原生协议使用 finx，不在客户端重新实现内核逻辑（protocol-design G2） |
| G3 | 零转换 | 协议消息从内核到页面，只在内核编码一次、在页面解析一次。主进程不解析、不改写（§3.2） |
| G4 | 原生手感 | macOS 上：隐藏式标题栏、侧栏材质、原生菜单与右键菜单、系统字体、深色模式、键盘操作 |
| G5 | 流畅 | 沿用基线的性能做法与指标（§9） |

### 1.2 一期范围

一期的目标是把 macOS 的外壳搭起来，界面完整可用，数据来自模拟服务：

- 主窗口：侧栏（新会话、搜索、会话列表、底部菜单）、会话页（对话、工具步骤、审批、运行状态、信息卡片）、输入框、新会话页、搜索面板、确认框与提示条。
- 会话列表的分组（按状态、按日期、按项目）、排序（最后活跃时间，最新或最早在前）、显示（元数据或仅标题）、折叠、归档的显示与隐藏。
- 设置窗口：通用页（外观、语言）、模型页（只读）。其余页面先占位。
- 原生应用菜单、右键菜单、快捷键；浅色与深色；中文与英文。
- 客户端逻辑包 `@finx/client` 与协议类型包 `@finx/protocol`。
- 打包成能双击打开的 FinxWork.app：自己的名称、图标、Bundle ID 与应用菜单，熔断开关打开，临时签名（本机运行）。

### 1.3 不在一期

- 连接真实内核（二期）。
- 应用里内置 finx、Developer ID 签名与公证、DMG、自动更新、通知、菜单栏图标、登录自启（三期）。
- Windows、Linux 的实现与验证（四期）。目录和接口一期就留好（§4）。
- 设置的细节：模型与厂商、审批规则、受保护路径、项目信任等。等内核与协议提供对应能力后再做。

## 2. 选型

### 2.1 候选

| | Electron | Tauri 2 | 每个平台一个原生壳 + 系统 WebView | 每个平台原生界面 |
|---|---|---|---|---|
| 三平台渲染一致 | 是，自带 Chromium | 否：WKWebView、WebView2、WebKitGTK 三种引擎 | 否 | 不适用，三套界面 |
| 增加的语言 | TypeScript | TypeScript + Rust | TypeScript + Swift + C# + C/GTK | Swift + C# + … |
| 安装体积 / 空闲内存 | 约 300 MB / 约 130 MB | 约 60 MB / 约 110 MB | 小 | 小 |
| 端到端测试 | Playwright 直接驱动，成熟 | WebDriver，不支持 macOS | 难 | 难 |
| 与内核的连接 | 主进程连接常驻服务 | 可以把内核链接进进程，也可以连常驻服务 | 连常驻服务 | 连常驻服务 |
| 已有经验 | 基线就是 Electron：打包、签名、公证、更新、DMG、端到端测试都已跑通 | 无 | 无 | 基线的签名器是 Swift |

### 2.2 结论：Electron + React（DD-01）

- **一个引擎覆盖三个平台**。系统 WebView 方案的短板在 Linux 的 WebKitGTK；三种引擎意味着同一份 CSS 要测三遍。
- **界面与外壳一种语言**。主进程、预加载、页面都是 TypeScript。
- **测试最好做**。Playwright 可以直接驱动 Electron 应用，界面流程都能写成端到端测试。
- **基线已经跑通全链路**。窗口与材质、原生菜单、`app://` 协议、沙箱、熔断开关（fuses）、签名公证、Squirrel 更新、DMG，都可以直接沿用，风险最小。
- **代价**：体积约 300 MB，空闲内存约 130 MB。对策：窗口关闭即销毁页面；不常驻的窗口不预建；三期在 CI 中记录体积与内存。

### 2.3 内核不进外壳进程（DD-02）

Tauri 方案可以把 finx-core 直接链接进应用进程，省掉一个进程。不这样做，理由是：

1. **生命周期**：任务应当独立于窗口。窗口关闭、页面崩溃、外壳升级，都不应该中断正在运行的任务。
2. **共享会话**：同一个会话可能同时被桌面端、编辑器（ACP）和命令行使用。内核在外壳进程里，别的客户端就只能拿到 `session_busy`（protocol-design §6.7）。
3. **协议已经设计了这条路**：protocol-design §2.1 的"自研客户端，常驻服务"就是 Unix socket ⇄ `finx serve --listen`，带多客户端、快照、断线重连。桌面端按这条路走，不需要另一套机制。
4. **开销可以忽略**：多出来的是一次本机 socket 读写，微秒级；事件的编码次数不变（§3.2）。

所以：**桌面端是 `finx serve` 的一个客户端**，和第三方客户端用同一套原生协议，没有私有通道。

## 3. 总体架构

```
┌─────────────────────────── FinxWork.app ───────────────────────────┐
│                                                                     │
│  页面 Renderer（React，沙箱）                                         │
│    界面组件 ── store ── @finx/client：RpcClient · 会话状态 · 列表逻辑   │
│                              ▲ │                                      │
│                              │ │ MessagePort：NDJSON 文本，原样转发      │
│                              │ ▼                                      │
│  主进程 Main（TypeScript）                                            │
│    窗口 · 菜单 · 偏好 · 文案 · 平台适配 · 内核连接（字节转发）            │
│                              ▲ │                                      │
└──────────────────────────────┼─┼──────────────────────────────────────┘
                               │ │ Unix socket（Windows：命名管道），NDJSON
                               │ ▼
              finx serve --listen（Rust，常驻服务）
                 finx-server → 原生投影 → finx-core（内核）
```

一期：右下角的 `finx serve` 由主进程里的模拟服务代替（§6.4），页面一侧的代码与二期完全相同。

### 3.1 进程

| 进程 | 语言 | 生命周期 | 能做 | 不能做 |
|---|---|---|---|---|
| 主进程 | TS | 应用运行期间 | 窗口、菜单、偏好、选择目录、在访达中显示、打开 https 链接；连接内核并转发字节 | 解析或改写协议消息 |
| 页面 | TS/React | 窗口打开期间，关闭即销毁 | 主进程通过桥给的能力；经 MessagePort 收发协议消息 | Node、文件系统、网络、远程内容 |
| finx serve | Rust | 常驻，空闲退出（protocol-design §8.2） | 全部内核能力，审批、受保护路径、项目信任照常生效 | — |

页面会显示别人写的内容（模型输出、工具输出、文件名），所以当作**可能被攻破**来设计：它拿到的能力，不超过同一用户的任何进程连上 socket 能拿到的能力。审批不能绕过（protocol-design §9）。

### 3.2 数据路径与零转换（DD-03）

```
内核：Event ──编码一次──▶ 一行 JSON（EventFrame，protocol-design §4.2）
主进程：socket 字节 ──截到最后一个 \n──▶ 一段文本 ──MessagePort──▶ 页面
页面：按 \n 切行 ──JSON.parse 一次──▶ RpcClient 分发 ──▶ 会话状态
```

- **主进程不解析**：它只按 `\n` 截断（保证每段都是完整的行），然后原样投递。积压时一段里自然会有多行，IPC 次数随之减少，不需要定时器。
- **请求同理**：页面 `JSON.stringify` 一次，主进程原样写进 socket。
- **字段名不转换**：TS 类型直接使用协议 JSON 的 snake_case 字段名，不建 camelCase 的映射层。
- **结果**：每个事件在整条链路上编码一次（内核）、解析一次（页面）。主进程只复制字节。
- **为什么用 MessagePort**：页面直接持有端口，消息不经过桥的代理函数；主进程一侧是 `MessagePortMain`，与 socket 对接。

### 3.3 内核的发现与拉起

已在二期实现，完整设计见 [desktop-kernel-integration.md](desktop-kernel-integration.md)。要点：

1. 应用内置自己的 finx（`FinxWork.app/Contents/MacOS/finx`），只用这一个版本（DD-10）。
2. 主进程的守护器先连接 `$FINX_HOME/run/finx.sock`；没有服务时以后台方式拉起 `finx serve --listen unix://… --idle-exit 600`，它脱离应用的进程组，退出应用不影响任务（DD-11）。
3. 拉起前解析用户登录 shell 的环境（PATH、密钥、语言），作为内核的环境（DD-13）。
4. 握手后核对版本与能力；不一致时先用着，等没有任务运行时替换成内置版本（DD-12）。
5. 内核断开后自动重新拉起并重连，页面以新快照恢复；60 秒内退出 3 次时停下，显示原因与日志（DD-17）。

### 4.2 平台适配（DD-04）

平台差异只出现在两个地方：

1. **主进程的平台适配**：一个接口，三份实现，`platform/index.ts` 按 `process.platform` 选择。

```ts
interface Platform {
  id: "mac" | "win" | "linux";
  /** 窗口的标题栏、系统按钮与材质。 */
  chrome(kind: "main" | "settings"): BrowserWindowConstructorOptions;
  /** 有没有应用菜单：macOS 有；Windows、Linux 隐藏菜单栏，按 Alt 显示。 */
  appMenu: boolean;
  /** 关掉最后一个窗口时退出应用（任务都在 finx 的服务里，不受影响）。 */
  quitWithLastWindow: boolean;
  /** 内核端点与内置二进制（二期）。 */
  kernelEndpoint(finxHome: string): string;
  kernelBinary(resources: string): string;
}
```

2. **页面的平台令牌**：`<html data-platform="mac|win|linux|web">`（web 是浏览器里的预览）。字体、字号、给系统按钮留的位置（`--lights` 左侧红绿灯、`--caption` 右侧系统三键）在 `tokens.css` 里按它取值。**组件里不写平台分支**。

| 方面 | macOS（一期） | Windows（四期） | Linux（四期） |
|---|---|---|---|
| 标题栏 | 隐藏式，红绿灯在 (20, 20)，与 52 px 顶栏对齐 | 隐藏式 + titleBarOverlay，系统三键在右 | 系统标题栏；以后可选隐藏式 |
| 窗口材质 | 侧栏透出 sidebar 材质，内容区不透明 | Mica | 无，纯色 |
| 应用菜单 | 有 | 隐藏，Alt 显示；页面里有全部操作 | 同 Windows |
| 字体 | 系统字体（SF），基础字号 13 px | Segoe UI Variable，14 px | 系统 UI 字体，14 px |
| 内核端点 | Unix socket | 命名管道（DQ-05） | Unix socket |
| 打包 | DMG + zip（更新用） | NSIS 或 MSIX | AppImage、deb |
| 登录自启 | SMAppService | 注册表 Run | XDG autostart |

### 5.3 会话列表

| 分组（按状态） | 条件 | 行上的标记 |
|---|---|---|

| 进行中 | 任务正在运行 | 标题流光 |

| 已完成 | 空闲 | 无 |
| 已归档 | 已归档且选择了显示 | 标题变灰 |

- 列表的视图、折叠的分组、选中的会话、侧栏开关，在重启后恢复。没有设置过视图时：按状态分组、最新在前、仅标题（不显示第二行）。

### 5.4 会话页

对话由会话状态（§6.2）推导，各协议元素的显示方式：

| 协议 | 界面 |
|---|---|
| user 消息 | 右侧深色气泡；悬停时下方右侧显示多久之前（"12 秒前 / 5 分钟前 / 3 小时前 / 2 天前"，一周以外是日期与时刻，再悬停看完整时间）和"拷贝"，模型的回复下方左侧同样有。时间一分钟内每秒刷新，一小时内每分钟，之后每十分钟。附带的图片、文件、文件夹是气泡上方的方块，与输入框里的相同（§5.5；附件块不作为正文显示） |
| assistant 消息的文字 | 正文 Markdown，GitHub 风格；代码块按语言着色；链接只开 http、https；不渲染原始 HTML，不加载图片 |
| assistant 消息的思考 | 折叠的一行"思考 · 摘要"，展开后是灰色正文。正在进行的思考不在步骤里，在对话末尾的运行行：标记右边"思考中 · 时间 · tokens"，下面是它最近的三行，新字从底部出来，顶部渐隐；点"思考中"展开全文（跟着滚到底，往上翻就停）。想完回到步骤里 |
| 工具调用与结果 | 一行灰字：动词 + 对象（命令用等宽字体并着色）。连续多个合成一组"读取了 2 个文件，运行了 3 条命令"。默认折叠，展开看输出；失败的动词标红 |
| tool_running 之前 / 之后 | 等待中不转圈，执行中转圈；等审批的调用动词为橙色的"待批准" |
| approval_requested | 底部审批卡片（§5.5）；这个调用在答复之前不出现在对话里，答复后作为普通步骤出现 |
| message_delta | 草稿：已完成的块各解析一次，最后一块用 remend 补全，避免出现半截 Markdown |
| stream_retry | 和失败同样的一行卡片，角标是橙色时钟：标题说是什么，下面"N 秒后第 K 次重试"，底边一条细线随等待缩短，右侧"停止"（打断任务）。重试开始出字或下一轮开始时消失 |
| task_failed | 一行卡片：左边是服务商的标志，右下角一个角标，颜色按这次失败要你做什么——蓝色是要先设置（没密钥、额度用完、上下文满），橙色是稍等就好（限流、繁忙、服务出错、网络、超时），红色是要改请求（内容过滤、请求无效、无法识别、未知）；中间是标题（"还没有 DeepSeek 的密钥"）和怎么办；右边一个主按钮：没密钥是"设置密钥"（存好后自动接着做），上下文满是"压缩并继续"（压缩结束后自动接着做），其余是"重试"；"···"菜单里是换个模型（选中有密钥的就接着做，没有的先要密钥）、重试、查看和拷贝原始报错。之后再有任务时，它收成一行灰字"这一轮没完成：……"，带同色的小圆点，点开看原始报错 |
| task_interrupted | 居中的一条小字"已打断"，退回的输入放回输入框 |
| task_completed（done） | 居中的一行灰字：完成 · 用时 · tokens · 费用 |
| task_completed（reason 不是 done） | 居中小字说明：达到轮次上限、输出被截断、被钩子结束 |
| 任务之间间隔较久 | 居中的时间线（今天 14:20、昨天 09:12） |
| `spawn_agent` 调用 | 派出卡片：标题"派出了 N 个子智能体，在后台并行工作"，一行一个子智能体：状态图标（执行中转圈、完成打勾、已中断暂停、失败红叉）、名字、任务的一句（按行和句号切分，取第一句别的任务没有的话，几个任务开头相同时跳过共同的开头；都一样时用第一句；去掉 Markdown 记号）、状态与用时（执行中每秒走）。同一条回复里连续的派出合成一张卡片。点一行打开后台面板并展开它（§5.10） |
| `send_message` 调用 | 一行灰字："已发消息给 名字：消息的第一行" |
| 带 `mail` 的 user 消息（子智能体的汇报） | 汇报卡片，不是本人的气泡：谁的汇报、状态标签、用时与 tokens（子智能体此刻的数，只标在与它当前状态相同的汇报上，它更早一轮的汇报不标）；正文是 Markdown，标题与正文同字号（汇报常以"## 报告"之类开头，不该占掉预览），较长时先显示两行，"展开全部"看全文；"查看执行过程"打开后台面板并展开这个子智能体。子智能体这一轮没有回复时（`mail.no_reply`，比如还没回复就被停下），正文换成一行灰字"停下时还没有回复"或"做完了，但没有回复"，不显示内核写给模型的说明 |
| 子智能体工作期间结束的任务 | 不显示完成行：子智能体的汇报还会把工作接下去。被停下的子智能体也算没做完：它的汇报留在收件箱里，等本人再说话时才交给 finx，这期间同样不显示完成行，对话末尾是橙色的"已中断"提示。最后一份汇报处理完、没有子智能体还在工作或停着等继续时，显示一行"完成 · 用时 · N 个子智能体 · tokens · 费用"，用时从这段工作开始时本人的消息算起，tokens 与费用是其间各任务之和 |

有后台任务在执行时，对话末尾有一行链接样式的提示"● 有 N 条后台任务正在执行 ›"，点它打开或收起后台面板；任务全部停下而汇报还没交给 finx 时，变成橙色的"N 条后台任务已中断，回复 finx 就能接着做"；都结束后消失。这一行在对话里随内容滚动，不占输入框上方的位置（§5.5 不放运行状态条）。

版式与基线一致：会话区铺满内容区，标题栏下一条铺满的细线；对话栏 730 px 居中（1240 宽的窗口里两侧各约 119 px）。信息卡片打开时浮在右上角（宽 252 px，距标题栏 21 px），对话让出 270 px，栏宽变为 630 px（起点 x=306），输入框跟随对话栏。

信息卡片的内容与基线同构：
- 有状态时先是状态块：状态与已用时间（运行中、等审批、出错）及一行说明（第几轮或错误类型）。
- 三行事实，各一个图标，要紧的名字加粗：模型与思考强度、审批模式、位置（上级目录 / **项目**；路径太长时先省略上级目录，项目名始终完整）。
- 一行汇总：任务数、tokens、费用、上下文占比（悬停看具体数字），不另加进度条。

### 5.5 输入框与审批

- **输入框**是一个组件（`Composer`），会话页与新会话页只靠属性 `form` 区分形态：`session` 浮在对话底部、上方可弹审批卡片、运行中可停止；`new` 在页面底部、下方多出运行环境与项目（§5.6）。两种形态的输入、附件、审批模式与模型完全相同。
- 会话页的输入框浮在对话底部正中，与对话同宽，圆角 22 px 的药丸形，底色 `--pill`（浅色白、深色 #28282c），细描边加柔和阴影。
  - 没有内容时只有一行，高 44 px：左边"+"，中间输入，右边发送；输入多行时向上长高（最多约 220 px，之后滚动）。⏎ 发送，⇧⏎ 换行；输入法组字时不发送。
  - 文字用 Lexical 的纯文本编辑器（§7 P13，skill-design §6.3.7）。任意位置打 `/` 在光标上方弹出菜单，开头还列出 `/compact`；按名字和描述过滤，带参数提示，↑↓ 选、⏎ 或 ⇥ 插入、Esc 关，没有匹配时不弹出，`a/b`、日期、网址里的 `/` 也不弹出。选中的 Skill 是一个带图标、只写名字的圆角标签，文字是 `/skill:名字`，一条消息可以有多个；手打或粘贴的完整写法也变成标签，反引号里的不算。标签整体删除，撤销能恢复。发出后，消息气泡里画出同样的标签，复制得到的是原话。
  - "+"向上弹出菜单：添加文件和图片（⌘U，菜单栏"文件"里同样有）、添加文件夹。加上的附件是输入框里文字上方的一排 96 px 的方块：图片铺满方块；文件、文件夹显示名字（最多四行）和类型（扩展名大写如 HTML，文件夹标"文件夹"），不放图标。悬停时右上角出现 × 去掉。点图片在窗口上方放大查看（灯箱，点任意处或 Esc 关闭，Esc 不会传给审批卡片）；点文件或文件夹在访达中显示它。发出后，消息气泡上方是同样的方块，交互相同。图片（png、jpg、gif、webp）作为协议的 image 内容发出：不超过 5 MB 且长边不超过 2048 px 的原样发送，否则在主进程里缩到长边 2048 px、转成 JPEG（例如 10.5 MB、1260×2736 的截图发出约 0.4 MB）；读不成图片的按文件处理。文件与文件夹以绝对路径写进消息末尾的一个文本块（"Attached files:" 开头，一行一个路径，文件夹以分隔符结尾），finx 的工具按路径读取，界面把这个块显示为标签而不是正文。协议有了附件内容之后改用它（§7 P11）。
  - 输入框下方、框外是一排安静的按钮（灰字，悬停才有底色），说明这条消息带着什么发出：左边审批模式（盾牌图标 + 模式名），右边模型与思考强度（"DeepSeek Flash 适中"，模型名深一级，强度浅一级；模型不支持思考时只显示模型）。模型菜单与其他弹出菜单同一样式：上面是模型（右侧灰字是厂商），分隔线下一行"思考强度 当前值 ›"，悬停或 → 打开它自己的子菜单（右侧放不下时开在左侧）。改模型、思考强度、审批模式即发 set_model、set_approval_mode。
  - 上下文占用不放在输入框附近，看信息卡片。
  - 发送与停止都在输入框里：任务运行中且没有输入时，发送按钮变成红色的停止按钮（打断，⌘. 同效）；一旦输入了内容，它又是发送，此时发送就是插话（PromptMode::Steer，下一轮生效），⌥⏎ 为排在任务之后（FollowUp）。
  - 输入框上方不放运行状态条（基线的"正在做什么 · 用时 · 打断"不要了）；运行状态看侧栏的流光与信息卡片。
  - 有待审批时，审批卡片在输入框正上方弹出（同宽、同样的圆角与阴影），输入框保持可用；答复后卡片收起。
  - 关键提醒也用这个位置和样子：内核带代码的 warning（protocol-design D-55）不进对话，而是在输入框上方弹出提醒卡片，与审批卡片同时存在时排在它上面。卡片第一行是橙色警示符号加粗体标题"关键提醒"，下面是几行灰色的内核原文，最后一行是"知道了"。
  - 绕过权限在切换进去的那一刻确认：输入框（会话页与新会话页）的权限菜单里选中绕过权限时，先弹出确认窗，标题"开启绕过权限？"，说明工具会直接运行、哪些情况仍会拦下、只在隔离环境里使用；按钮"拒绝"（模式不变）与"同意"（切换过去）。每次从别的模式切进绕过权限都确认一次，停在这个模式期间不再有任何提示。内核加载绕过权限的会话时发的那条提醒（D-55，留给命令行与其他客户端）界面不显示；不是在应用里切进去的会话（命令行启动、配置文件默认），只靠权限按钮上的模式名提示。
  - 每个会话没发出去的草稿各自保留；打断时退回的输入放回空的输入框。
- **审批卡片**三行，约 130 px 高：
  - 第一行：问题（"运行这条命令？""修改 NOTES.md？"）加粗，后面是灰色的原因；多条待审批时右端标出"第 1 / 3 项"，按提出的顺序答复。
  - 第二行：调用本身。命令按 shell 着色；edit 显示删掉与加上的行（红绿两色）；write 显示开头几行；其他工具显示参数。超过 12 行时注明还有几行。
  - 第三行：按钮，一次点击即答复。左边"拒绝…"（在原处展开一行说明，交给模型）；右边"本会话都允许"（悬停说明规则或前缀）和"允许 ⌘↩"。卡片里不放打断，停止整个任务用输入框的停止按钮。
  - 键盘：⌘↩（菜单"批准"）在任何地方都是允许一次；焦点不在输入框时，↩ 或 1 允许，2 本会话都允许，Esc 或 3 拒绝。

### 5.6 新会话页

- 中间是 finxwork 的标志（52 px）和一句话，每次打开随机一句（"让我们开始一个任务吧""今天想一起做点什么？"等四句，中英各一套）；输入框在底部，与会话页的同位置、同样式。
- 与会话页的输入框只差在下方那排按钮：左边依次是运行环境、项目、审批模式，右边是模型与思考强度。
  - 运行环境：一期只有"本机"（在这台电脑上运行）；"云端"列在菜单里、标"即将推出"、不可选。云端做的时候，环境决定 `session/new` 发给哪个 finx。
  - 项目：最近的项目（按会话的 cwd 统计，无项目的会话不算，P8）+ "无项目" + "选择文件夹…"（原生对话框）；默认最近用过的项目，没有时默认无项目，刚选的文件夹排在最前。无项目时 `session/new` 不带 cwd，内核为会话新建一个空文件夹（P14），会话页的环境卡片显示"无项目 · 会话自己的文件夹"，菜单仍可在访达或终端中打开它。
  - 不做 worktree 选项。
  - 以上选择都会记住。
  - 记住的模型所在的服务商已经不在（本机连接断开或删除）时，按钮显示默认模型，发送也用默认模型；连接回来之前不会再选到它（P15）。
- 发送即 `session/new`（cwd 为所选项目；"+"添加的文件夹作为 `extra_roots`，成为这个会话的工作区根目录）加第一条 `prompt`（文字、图片、文件路径），左侧列表立即出现这个会话（标题先用第一条消息）并选中它。
- 出错时的提示条在内容区上方居中，宽度不超过内容区（左右各留 16 px，最宽 560 px），长文字换行，最多三行，超出的截断。
- 已开始的会话里再添加文件夹，一期只把路径告诉模型；把它加为工作区根目录要等内核支持（§7 P10）。

### 5.7 设置窗口

- 独立窗口（⌘,），布局同系统设置：左侧页面列表，右侧页面内容，顶栏 52 px。
- 通用：外观（跟随系统、浅色、深色，立即生效）；语言（跟随系统、简体中文、English，改后提示重启）。
- 模型：只读列出 `models/list` 的厂商（地址、线协议、密钥状态）与模型（默认、是否支持思考、上下文窗口）；编辑在连接内核后提供。
- 权限：占位，列出二期要做的项（默认审批模式、命令规则、受保护路径、项目信任）。
- 关于：版本、内核（演示或 finx 的版本）、数据目录。

### 5.9 文案与语言（DD-08）

- 两种语言：简体中文与英文。英文文件包含全部键，中文翻译它们；键的类型从英文文件推导，缺键在编译时报错。

### 5.10 后台任务面板

后台任务目前只有子智能体一种（subagent-design），面板按"后台任务"设计，以后的其他类型（例如后台命令）放进同一个列表。

- **入口**：会话有子智能体时，顶栏信息卡片按钮的左边多一个按钮（叠放图标），有任务在执行时右上角是执行中的数量；对话末尾的提示（§5.4）、派出卡片的行、汇报卡片的"查看执行过程"、信息卡片里的"查看后台任务"都打开它。
- **位置**：窗口右侧单独一栏，宽 340 px，从窗口顶边到底边，与左侧边栏对称。底色是与内容区相同的实色，不透明；左边一条细线和对话分开，面板里不用卡片，也不加边框。打开时对话栏变窄，让出这一栏；信息卡片与它同时只显示一个。视口窄于 1180 px 时，面板盖在对话右侧，对话不让位。Windows 上系统的窗口按钮落在面板顶部，面板顶部为它们留出位置。
- **顶部**：与对话的顶栏同高（52 px），可以拖动窗口。左边是标题"后台任务"；有任务在执行时右边是"全部停止"（灰色文字按钮，悬停变红；停止整个会话，Op `interrupt`），最右是关闭。
- **列表**：先是一行分组行样式的数量（"2 个执行中 · 1 个已中断"，全部完成时"全部完成"），右端是合计的 tokens。每个子智能体一行，样子同边栏的会话行。第一行是名字：执行中时名字流光，右端的用时每秒走；已中断时右端是橙点加"已中断"，失败是红点加"失败"；完成后右端是这一轮的用时。第二行是任务的一句，取法同派出卡片（§5.4，在面板的全部任务里区分）。选中的一行有选中底色。
- **执行过程**：点一行选中它，再点取消；列表下方显示它的执行过程，占满剩余高度。开头是一行分组行样式的"名字 的执行过程"，执行中时右端是"停止"（只停这一个，Op `agent_interrupt`）。下面是它自己的对话：先是"finx 的任务说明"（灰色小字标明是谁说的，正文超过三行时折叠，"展开全文"），finx 后来发的消息也是一段带标注的文字；它的步骤一步一行，不合并成组；最后是它的汇报与完成行。执行中自动跟到最新一步，往上翻时不跟。已中断时末尾是一行橙色的"已中断 · 保留着进度，回复 finx 就能让它接着做"。
- **信息卡片**：会话自己没有任务、子智能体还在工作时，状态块是"后台运行中"与已用时间，下面一行"N 个子智能体在工作 · 查看后台任务"。
- **会话列表**：子智能体工作期间，会话一直在"进行中"，标题流光，时间从这段工作开始时算起（服务层的摘要按此给出 state 与 task_started_at）。

## 6. 客户端逻辑

### 6.1 RpcClient

```ts
interface Transport {
  send(text: string): void;                           // 一行或多行完整的 NDJSON
  onText(cb: (text: string) => void): () => void;     // 收到的文本，可能含多行
  onClose(cb: () => void): () => void;                // 连接结束
}

class RpcClient {
  request<M extends keyof AllMethods>(method: M, params: AllMethods[M][0]): Promise<AllMethods[M][1]>;
  notify(method: string, params: unknown): void;
  on<N extends keyof AllNotifications>(method: N, cb: (params: AllNotifications[N]) => void): () => void;
}
```

`AllMethods`、`AllNotifications` 是协议方法与 §7 提议方法的合集，方法名、参数、结果都有类型。

- 请求 id 用递增整数；挂起表按 id 找回 Promise；错误按 protocol-design §6.7 的 `data.kind` 抛出带种类的异常。
- 连接断开时，挂起的请求全部以 `disconnected` 失败；重连由调用方负责（§3.3 第 4 条）。

### 6.2 会话状态

每个打开的会话一份，规则与服务层的会话镜像一致（protocol-design §3.5）：

1. `session/attach`（或 `resume`、`new`）拿到快照：`transcript`、`active_task`、`usage`、`last_seq`。
2. 之后的事件只应用 `seq > last_seq` 的；seq 可能不连续（合并）。
3. 收到 `session/detached` 时，重新接入，以新快照整体替换。
4. 状态是不可变的：每个事件产生新对象，没有变化的部分沿用旧对象，界面据此只重画变了的行。
5. 增量（message_delta、tool_progress）按帧合并：一帧之内到达的多条增量只触发一次渲染。

由状态推导：会话的状态（空闲、运行中、等审批、出错）、对话步骤（§5.4）、正在生成的草稿、待审批列表、用量与上下文占用。

### 6.3 列表与搜索

- 列表数据来自 `session/list`，之后由 §7 P1 的推送更新。一期由模拟服务推送。
- 分组、排序、搜索是纯函数（`sessions.ts`），单元测试覆盖。搜索匹配标题、项目、模型，"需要处理"在前，其次"进行中"，再按时间。

### 6.4 模拟服务（DD-06）

- 用 TS 实现原生协议的服务一侧：`initialize`、`session/list`、`session/new`、`session/resume`、`session/attach`、`session/detach`、`session/op`、`session/close`、`session/delete`、`models/list`，以及 §7 中提议的方法。
- 按真实格式推送事件：任务开始、轮次、消息增量（按字切分，带随机节奏）、工具开始、执行中、进度、完成、审批请求与答复、任务结束。
- 演示数据：一个由 examples/snake-game 的真实会话日志转换来的会话，加上处在各种状态的若干会话（运行中、等审批、出错、空闲、已归档），覆盖界面的所有分支。
- 一期它运行在主进程里，接在 MessagePort 的另一端，所以页面一侧走的是二期的真实路径；在浏览器里单独预览页面时，它运行在页面里。
- 二期之后它继续用于开发和端到端测试。
- Skill：`skills/list` 的两种形式返回四个演示 Skill 和 `/compact`；用户消息按提及带上 `skills`（P13）。

| P15 | 模型不可用 | 记住的模型所在的连接已断开或删除时，界面说清楚并让人换模型，不显示内核的原文 | 已实现（protocol-design v0.18）：`session/new` 要的模型所属服务商不存在时返回错误 −32022 `model_unavailable`，data 带 `provider`；客户端在 `models/list` 的服务商里找不到所选模型的服务商时改用默认模型（`packages/client/src/models.ts` 的 `draftModel`） |

## 8. 安全

沿用基线的做法：

- 页面：`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。
- 页面从内置的 `app://` 协议加载（防路径穿越），不用 `file://`；CSP 为 `default-src 'self'`，不允许 WebAssembly 与远程脚本。
- 禁止页面导航和打开新窗口；外部链接经主进程打开，只允许 https。
- 主进程处理每个 IPC 请求前，校验发送方是自己的页面。
- 模型输出按 Markdown 渲染，不渲染原始 HTML；代码着色的结果是 React 元素，不是 HTML 字符串；图片只显示替代文字。
- 打包时打开熔断开关：关闭 RunAsNode、NodeOptions、命令行调试；打开 ASAR 完整性校验与只从 ASAR 加载（`scripts/build-app.mjs`）。
- 页面拿不到 socket 路径和任何密钥；审批只能经 Op 答复，不能绕过（protocol-design §9）。

## 9. 性能

沿用基线的指标与做法：

| 指标 | 目标 |
|---|---|
| 切换会话：点击到对话出现 | ≤ 33 ms（不含内核读取快照的时间） |
| 输入到下一帧（点击、打字） | p50 ≤ 33 ms，最大 ≤ 100 ms |
| 什么都没变时页面主线程 | ≤ 1 % |
| 长任务流式输出时页面主线程 | ≤ 10 % |
| 超过 50 ms 的动画帧 | 0 |
| 打开 20 个会话再回来，GC 之后 | 堆与 DOM 节点无增长 |

做法：

- 动效只用 transform 与 opacity，由合成器执行（运行中标题的流光）。
- 一个间隔只有一个时钟，所有计时在同一帧变化。
- 列表行、对话行用 memo，只在显示的内容变化时重画。
- 增量按帧合并（§6.2 第 5 条）。
- `app://` 打开 V8 代码缓存。
- 长对话：先渲染快照里的最近 100 条，向上滚动时用 `session/history` 分页（protocol-design §6.4）。
